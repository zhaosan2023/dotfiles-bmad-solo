# BMRalph V5 核心流程

## 路由与接管

1. 先判断只读、结晶、实施、继续或重放意图。显式指定计划时仅读取该候选，跳过默认暂存入口；缺失、权限拒绝、磁盘错误和格式损坏分别报告，不静默换计划。
2. 无显式路径时仅探测相关的默认暂存候选。默认入口缺失是正常状态；新任务不默认搜索归档，不让无关或未完成计划抢占当前任务，不无条件覆盖活动任务。
3. 仅明确继续历史任务时发现归档候选并说明匹配依据；历史输入只读，恢复或重放须明确授权、建立保留来源的新实例并重新验证，不继承历史绿灯。
4. 明确小修复或运维可走轻量路径，不强制完整分析、计划或 ADR。只读任务不实施、不验证、不转正或归档。
5. 接管、契约变化与阶段边界核验计划元数据、关联 ADR、目标、授权及验收，绑定实际路径、标识、契约版本和阶段。未知会话标识保持 null；不逐修改绑定，不要求模型手工计算或同步指纹。外部契约变化先停止对账。
6. 按权限读取项目事实基线和相关源码，保护既有改动；分析入口不得为检查 Git 绕过终端限制。

## 验证选择

- algo：仅适用的算法约束、性能与阶段验证；重要架构边界变化时预检。
- structural：针对受影响接口、数据所有权与跨层依赖预检，执行契约指定的配置、隔离分发或相关单测；不追加算法或无关业务测试。
- bugfix：改动相关测试与自审，不强制架构预检或建立、转正 ADR。
- ops：差异审查与配置语法检查，不运行业务单测。
- 获准阶段的必需验证资产缺失时先实现，不以帮助命令、日志保存或零命中替代测试通过。
- 控制器真实可用且操作覆盖验证时使用类型化入口；否则披露缺口，沿用获准命令及宪章的串行、超时、同步、输入封闭和工具正交要求。

## 唯一进度与证据

- V5 目标状态职责：绑定计划的任务清单是唯一任务进度，保存未完成事项和必要发现；状态卡只是程序生成的只读视图，不另建人工状态账本。稳定目标、授权、关键决策与验收不随普通任务拆分改写。
- 控制器尚未实现或未覆盖本次操作时，当前平台任务记录是唯一临时进度入口，引用真实工具回执并披露缺口；不同时在计划维护第二份进度，不宣称已具备程序防篡改保证。迁移状态职责须明确接管边界。
- 回执保存实际命令、工作目录、退出结果、关键输出和目标；ADR 只保存决策与依据，计划不镜像逐轮验证流水。
- 保存进度不触发业务重测。相关实现、测试、契约或环境变化后仅重验受影响证据；无关文档变化不触发重复验证。
- 接管输入仅含当前目标、授权、至多 80 行且受字节预算限制的状态视图、相关约束和差异定位。保留全部未完成事项，无法在预算内完整表示时报告预算阻塞，不静默丢弃。
- 启动输入与累计工具输出分别设预算；能数 Token 时用 Token，否则披露字节近似。完整日志留在授权任务工作区，不默认注入历史或附件，不宣称覆盖宿主工具旁路。

## 推进、停止与交付

- 状态：INTAKE → READ_ONLY / IDLE / NEEDS_SELECTION / READY；获准实施后 READY → EXECUTING → VERIFYING → COMPLETED → ARCHIVED。执行失败、超时或缺必需证据进入 BLOCKED；明确暂停进入 SUSPENDED，获准恢复并重验边界后进入 READY。
- 普通验证失败可在预算内修复，但任务不完成、不推进依赖；权限拒绝、认证不足、预算耗尽、持续无进展或无法确认进程结束时明确停止并保留成果。
- Ralph 仅为获准任务期进程，不建设永久平台。每轮启动新工程会话，不自动续接旧聊天；生产服务与编码工作区、账号及验证环境隔离，一个工作区一个活动写入者。
- 安装、更新、部署及 IDE 重载不启动 Ralph、不准备模型认证。活动任务期间不得替换绑定的规则或程序；更新或回切须先停止并确认在途进程结束。
- 阶段交付不标记全计划完成；不得通过自行放宽验收制造通过。真实宿主、权限和断开自主执行只按对应实测报告。
- 全部必需门禁通过且契约要求并获准转正时才接受关联 ADR；缺运行时证据保持 PROPOSED。事实基线仅登记已验证事实及溯源。
- 仅归档绑定、已完成且获准归档的活动计划。目标包含时间与计划标识，禁止覆盖；完整保存目标后复核源标识与内容版本，失败保留源。历史输入、其他暂停任务和无计划轻量任务不参与归档。
