# 代码审查流程

## 输入与授权

- 遵循[核心规则](../../../../rules/bmad-core.md)及[工程规则](../../../../roo/rules-bmad-engineer/01-bmad-engineer-core.md)。审查不扩大实施、验证或生产操作授权。
- 定向读取当前需求、获准验收、绑定计划、相关源码及调用方；关联 ADR 仅用于核对关键决策。
- 使用实际实现差异与真实验证回执，不将开发叙述、完成口令、文件变化或历史通过记录作为当前通过证据。
- 当前任务进度只读取实际权威入口：受覆盖控制器核验的计划任务清单，或控制器未覆盖时的平台任务记录；不要求固定路径，不建立第二份账本。
- 只读审查不修改文件、不运行验证、不转正或归档。证据缺失时说明缺口，不用任务复杂度扩大权限。

## 核心检查

1. 正确性：实现是否满足当前目标和稳定验收；边界、错误路径及不适用项是否有明确依据，是否悄悄放宽了承诺。
2. 验证：回执是否包含真实命令、工作目录、退出结果、关键输出和目标；是否覆盖当前实现，是否存在零命中、必需项跳过或被降低的断言。
3. 失败传播：测试失败但日志或状态保存成功时，整体是否仍判失败；超时、取消、缺依赖、缺证据或清理失败是否阻断推进。
4. 架构：重要接口、依赖方向、数据所有权及并发边界是否保持获准决策；套件源码和任务工作区是否分开，是否引入跨版本运行依赖。
5. 安全：是否保护用户已有改动、第三方资产和失败轮次成果；输入、路径和权限是否受实际实现约束，是否夸大同账号文件的防篡改能力。
6. 上下文：有界摘要是否明确截断，是否保留全部必要未完成事项和有效失败反馈；80 行视图是否被误当作整个请求预算。
7. 状态与证据：相关实现、测试、契约或环境变化后是否失效受影响证据；保存状态和无关文档修改是否错误触发重测或重复账本。
8. 运行边界：是否将静态配置、临时根分发、本地模拟或进程存活外推为真实宿主加载、工具权限或断开后的自主推进。
9. 维护成本：是否存在无关重构、依赖升级、大型索引或多文档镜像；实现与文案是否准确披露尚未覆盖的能力。

## 结论与处理

- APPROVE：当前获准范围的实现与必需证据充分，未发现阻断问题；不代表其他阶段或全计划完成。
- APPROVE_WITH_DEBT：仅存在非必需门禁的轻微问题，明确其影响及后续处理；不能用此结论豁免失败或缺失的必需证据。
- CHANGES_REQUIRED：存在可修复的实现或验证缺陷，按[实施流程](build.md)在获准范围内修复后重验受影响证据。
- ARCHITECTURE_DECISION_REQUIRED：目标、授权、关键决策或验收存在实质冲突，停止受影响部分并请求决定，不自行改契约过关。
- INSUFFICIENT_EVIDENCE：缺少必需证据、验证目标不明确或证据已失效；获准实施任务的受影响阶段保持 BLOCKED，只读任务仅报告证据不足。

这些结论仅用于审查交付，不新增计划生命周期状态。结论必须定位具体缺陷、影响及证据，不能复述开发说明代替独立检查。

## 交付边界

- 会话交付简短结论及必要问题定位；不默认创建持久审查报告，也不在计划或 ADR 镜像逐轮流水。
- 保留全部未完成事项。阶段通过不标记全计划完成，静态检查不证明目标运行时。
- 缺必需运行时证据保持关联 ADR 为 PROPOSED；转正、归档、提交、推送、真实宿主和生产部署分别受契约及实际授权约束。
