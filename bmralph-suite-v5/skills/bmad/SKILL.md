# BMRalph V5 工程

直接实施用户明确需求或获准方案，不重复生成分析，不模拟角色会议。

- 遵循[套件核心规则](../../rules/bmad-core.md)与[工程规则](../../roo/rules-bmad-engineer/01-bmad-engineer-core.md)。显式计划优先，默认入口缺失正常，历史恢复须授权、新实例和重验。
- 先确认真实工具权限、目标、范围、验收与已有改动；只读任务不实施、不验证、不转正或归档。
- algo、structural、bugfix、ops 按改动选择相关门禁，不全库盲测、不对所有任务强制预检。小修复不要求先建立完整计划或 ADR。
- 使用已实现并覆盖当前验证的类型化执行器；未覆盖时披露缺口并沿用获准受控命令，不把拟议程序当作已有能力。
- 唯一进度按核心规则接管：计划任务清单与程序只读视图是目标职责；控制器未覆盖时临时使用平台任务记录引用真实回执，不同时维护镜像。
- 只携带当前目标、授权、必要约束、代码定位、未完成修改及有效失败反馈；状态至多 80 行且受字节预算限制，启动输入和累计工具输出分别限额。
- 普通失败预算内修复，但失败、超时、缺证据不推进。保存状态不重测，相关变化仅失效受影响证据。
- 远程独立运行时、预算、工具权限及断开两轮行为须另验；安装或 IDE 重载不启动任务。不得静默更换引擎。
- 全部门禁通过且获准时才执行关联 ADR 转正及绑定式归档；局部交付保留全部未覆盖验收。提交、推送、真实宿主和生产部署分别授权。

按需使用[能力导航](references/capability-map.md)定位[实施流程](references/procedures/build.md)和[审查流程](references/procedures/code-review.md)，不默认加载全部流程或历史；文档存在不证明运行程序或宿主技能已可用。

需要新计划时使用[本套件模板](references/templates/implementation-plan.template.md)，不得覆盖未经授权的未完成活动任务。
