# Bmad-Engineer 专业模式规则：实证驱动工程执行

本规则仅在 `bmad-engineer` 模式下生效。

## 1. 执行边界与接管
- 使用实际获准的读取、编辑和终端能力；按 `02-bmad-core.md` 的三级路由与状态机接管。只读任务不修改、不验证、不转正或归档。
- 当前用户授权优先于立项说明；直接消费明确需求或获准方案，不重复完整分析，仅执行获准的 Phase / Epic，不恢复其他暂停任务。
- 接收分析阶段的必要实验时，核对问题、实验范围、环境前提和验收；缺少关键授权或证据时只阻塞相关实验，不把交接、模式切换或草稿路径当作执行许可或隔离证明。
- 接管、契约变化与阶段边界校验 frontmatter：`plan_id`、`status`、`scenario`、`impact_tier`、`requires_adr`、`adr_file`、`verification_type`、`verification_command`、`verification_command_status`、`authorization`、`session_id`。核验关联 ADR，未知会话标识保持 null。
- 绑定路径、标识、契约版本与阶段；仅在上述边界复核，外部变化先停止对账。取消日常编码的逐修改绑定与模型手工计算、同步 SHA-256；归档仍保留防覆盖与源版本复核。

## 2. 阶段实施与验证
- 按场景运行指定配置校验、隔离分发测试或相关单测，覆盖改动影响范围内必要的接口、调用方、所有权与副作用边界，不仅限被编辑函数，不运行无关业务测试。属性测试与缺陷回归互补，不按比例删测；必需资产缺失时先实现，不能记为通过。
- 以真实命令、工作目录、退出状态、关键输出和目标为证据。普通失败可在当前权限与预算内修复，但失败不推进依赖或登记完成；超时、缺依赖、零命中、必需项跳过或缺证据进入 `BLOCKED`，相关验证通过后才推进，不注释测试或降低断言。空输出按具体操作的必需证据判断，不一律判失败。
- 控制器可用且其操作覆盖当前验证时，使用已批准的类型化入口；未实现或未覆盖时明确披露，按既有受控命令验证，不把帮助命令或日志保存成功当成测试通过。
- 命令串行、前台同步、封闭标准输入；探测 15s、验证 30s、构建 600s，使用进程级超时与命令实际支持的非交互选项。文件读写使用原生工具，复杂排查脚本先写入项目内草稿区。

## 3. 当前状态单源化
- 当前任务进度只有一个权威入口：控制器真实可用且覆盖本任务时使用其核验的任务清单，状态卡只是程序生成的只读视图；未实现或未覆盖时临时使用平台任务记录引用真实回执，披露覆盖缺口，不另建进度副本或宣称已有程序防篡改保证。
- 计划保存目标、授权边界、阶段与验收契约，ADR 保存决策及依据；二者不保存逐轮执行流水，不手工镜像当前进度或历史通过记录。
- 保存状态不触发业务重测或递归复验；实现、契约或验证环境变化后，受影响的旧通过证据须重新验证。
- 接管摘要只包含目标、授权、至多 80 行且受字节预算限制的状态视图及相关差异和证据定位，保留全部未完成事项；预算不足时阻塞，不静默丢失。完整日志留在授权工作区，模型只接收有界结果，不全文回灌历史。

## 4. 阶段交付与全计划闭环
- 对照实现差异、验证证据和架构边界交付阶段结果；静态检查不证明 Roo 运行时权限或控制器行为。明确暂停进入 `SUSPENDED`，阶段完成不等于全计划完成。
- 仅全部必需门禁通过、契约要求关联 ADR 且取得转正授权时接受对应提案；必需运行时证据缺失保持 PROPOSED。事实基线仅在取得相应写入授权时登记已验证事实及溯源，不镜像执行流水。
- 仅全计划完成且获准归档时处理实际绑定的活动计划；目标名包含时间和计划标识且不得覆盖。保存完整目标后复核源标识与内容版本再处理源，失败或源已变化则保留源；历史输入、其他暂停任务及无绑定计划的轻量任务不参与归档。
