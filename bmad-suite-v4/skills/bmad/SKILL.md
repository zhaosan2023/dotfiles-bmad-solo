# BMAD-Solo V4.2 Router (Adaptive Empirical Engine)

## Objective

Complete the user's task through one continuous, disciplined AI session.
Do not simulate a multi-agent meeting. Do not force users to memorize internal procedure names.
The AI automatically detects task scenario fingerprints, dynamically mounts corresponding safety valves,
and uses real test feedback as the ultimate arbiter of truth.

---

## 1. 意图、授权与三级计划路由

先判断只读、结晶、实施、继续或重放意图，并核验实际工具权限。读取计划不等于获得执行授权；只读任务仅取证和会话交付，不写文件、不运行验证、不转正或归档。

工程直接消费明确需求或获准方案，不重复完整分析。接收必要实验时核对问题、实验范围、环境前提和验收；交接或模式切换不构成启动授权，草稿路径不提供执行级隔离。分析角色不使用终端、不创建或执行探针。

1. **显式指定优先**：用户指定计划时只读取该候选，跳过默认暂存入口。指定文件缺失或非法时报告可恢复阻塞，可发现候选，不静默替换任务。
2. **活动计划探测**：无显式路径时才探测 `_bmad-output/pending_implementation_plan.md`；相关且有效才绑定，无关计划不抢占，多任务冲突时请求选择。
3. **归档与空闲降级**：默认入口缺失是正常状态，不重复盲读。继续历史任务时检索 `_bmad-output/archive/plans/` 并展示匹配依据，不自动执行最新归档；候选不明时请求选择，无候选时按意图空闲或提出新方案。明确的小修复与运维任务可走轻量路径。
4. **恢复边界**：文件缺失、权限拒绝、磁盘错误和格式损坏分别处理。历史计划默认只读，恢复或重放须显式授权，建立保留来源的新执行实例并重新验证，不继承旧绿灯或覆盖历史输入。
5. **契约绑定**：在接管、契约变化与阶段边界校验 `plan_id`、`status`、`scenario`、`impact_tier`、`requires_adr`、`adr_file`、`verification_type`、`verification_command`、`verification_command_status`、`authorization` 和 `session_id`。绑定路径、标识、契约版本与阶段；外部变化先停止对账，取消逐修改绑定和模型手工计算、同步指纹。当前用户授权优先于立项说明，在唯一任务记录中注明差异，不编造会话标识。
6. **事实与平台适配**：读取 `_bmad-output/project-context.md`；仅在权限和任务允许时执行 `timeout 15s git --no-pager status --short < /dev/null`。使用当前平台实际提供的任务跟踪能力；不强制写入未知的应用目录，不编造会话路径，不绕过工作区边界。

状态契约：`INTAKE → READ_ONLY / IDLE / NEEDS_SELECTION / READY`；获准实施后 `READY → EXECUTING → VERIFYING → COMPLETED → ARCHIVED`。失败进入 `BLOCKED`，明确暂停进入 `SUSPENDED`，获准恢复后重新校验再进入 `READY`。

当前任务进度仅用一个权威入口：控制器真实可用且覆盖本任务时使用其核验的任务清单，状态卡只是程序生成的只读视图；未实现或未覆盖时临时采用平台任务记录及真实回执，披露缺口，不宣称已有程序防篡改保证。计划与 ADR 不保存逐轮执行流水，不另建进度副本或镜像历史通过记录。保存进度不触发业务重测；实现、测试、契约或环境变化后仅重验受影响证据。接管仅提供目标、授权、状态视图与相关差异和证据定位；80 行与配置字节预算是默认规划目标。先保留全部未完成事项及必需支持闭包，再去重和无损压缩；纯软超限仅结构化提醒并记录完整预算遥测，按双方声明能力协商大帧或分片。实际硬能力不足、未协商能力或必需信息缺失才阻塞，不静默丢失，不扩大外发范围、请求数或时限，不全文回灌历史。

## 2. 场景自适应动态背压

场景决定验证类型，实际影响范围决定深度；不采用所有任务都经历全部流程的固定流水线，不通过改变场景标签豁免必需验收。

| 场景 | 必要检查与验证 | 不机械附加 |
|---|---|---|
| 算法 | 算法适配、架构边界、性能等必要约束及相关验证 | 无关全库测试 |
| 结构 | 接口、数据所有权、跨层依赖，按契约选择配置、隔离分发或相关回归 | 无关算法检查 |
| 缺陷 | 最小充分缺陷回归、调用方与必要副作用边界、自审 | 重型预检、完整重规划、ADR |
| 运维 | 差异审查、配置语法及受影响的分发验证 | 无关业务单测 |

复杂工作按实际依赖拆分 Epic/Task，轻量工作不强制持久计划。自动拆分、内部技能路由及宿主模式切换都不能扩大当前授权。

普通失败保持授权和预算内的修复通道，但不得登记完成或推进依赖。公共接口、所有权等发生实质变化，或同类修复连续失败两次，进行必要重检；重检不自动启动实验或扩大实施范围。实现、测试、契约或环境变化后，只重验受影响证据；旧证据不能批准已变化的候选。

这里定义的是方法论契约，不是已实现的程序拦截。Cline 原生 Plan/Act 无需技能口令的承载及执行前、验证后、推进前门禁必须分别适配和验收；宿主自动批准、模型勾选清单和任务完成提示不等于项目质量放行。控制器未实现或未覆盖时披露缺口，使用获准受控命令及平台任务记录，不宣称已有硬隔离或程序防篡改保证。

项目导航与规范保存当前操作入口和不变量，ADR 保存取舍与依据，计划保存授权、依赖及验收，长期测试保存回归，临时验证与原始证据按实际保留需要管理。项目内容单源，原生会话规划不生成第二份权威执行计划，摘要不代替唯一原始回执；项目私有规范、计划与证据不进入全局方法论分发。

### 场景 1：算法与高能计算型 (`scenario: algo`)
- *适用范围*：K线、缠论、相空间动力学、回测微服务、极速监控循环、ClickHouse 批量入库。
- *强制安全阀*：
  1. **挂载 `algorithm-fit.md`**：硬性审查 NFR（单循环延迟上限、内存预算、抗过拟合边界）。严禁无回测依据的参数过拟合！
  2. **挂载 `architecture-preflight.md`**：检查数据流与通道契约。
  3. **阶段验证背压**：运行契约指定的相关验证，必需失败不推进依赖；程序强制能力按实际覆盖情况披露。
  4. **阶段对账**：核对实际实现与必需证据；仅契约要求且另获授权时处理关联 ADR 转正，不自动触发事实登记或归档。

### 场景 2：系统结构与重构型 (`scenario: structural`)
- *适用范围*：多模块解耦、公共接口改造、数据迁移、服务分层。
- *强制安全阀*：
  1. **跳过 `algorithm-fit.md`**（零算法开销）。
  2. **挂载 `architecture-preflight.md`**：重点审查数据所有权、公共接口兼容性与跨层调用。
  3. **阶段验证背压**：按影响范围选择配置校验、隔离分发或相关回归，必需失败不推进依赖，不把规则文字当作程序强制证据。
  4. **阶段对账**：核对实际实现与必需证据；仅契约要求且另获授权时处理关联 ADR 转正，不自动触发事实登记或归档。

### 场景 3：局部缺陷修复型 (`scenario: bugfix`)
- *适用范围*：单组件修复、参数微调、前端样式修复（S/M 级小任务）。
- *行为准则*：
  1. **跳过 Preflight、跳过 Algorithm-Fit**（杜绝形式主义卡死）。
  2. **最小充分相关回归**：覆盖改动影响范围内必要的接口、调用方与副作用边界，不仅限被编辑函数，不盲跑全库；属性测试与已发现缺陷的回归互补，不按比例删测。
  3. **不建立、不转正 ADR**：防止日常补丁稀释架构总账。

### 场景 4：运维协同与配置型 (`scenario: ops`)
- *适用范围*：Git 提交推送、`./bs.sh` 镜像分发、配置校验、文档更新。
- *行为准则*：
  1. **严格遵从收敛锁 4**：严禁启动容器执行业务单元测试！
  2. **按实际改动选择差异审查、配置语法及必要分发验证**；差异审查通过不等于工作树没有用户修改，不运行业务单测。
  3. 杜绝重型架构开销。

## 3. Epic 阶段验证门禁

获准工程实施后，按绑定计划的每个阶段执行以下门禁。根据验证类型和改动范围选择配置校验、隔离分发测试或相关单测，不运行无关业务测试；验证资产尚未创建时先完成其实现，缺失不能记为通过。静态权限用例与参考路由模型不证明目标 Roo 的实际权限执行或模型行为。

1. **按阶段实施**：只实施当前获准单元，保护已有改动，不提前启动依赖未通过的阶段。
2. **相关验证门禁**：
   - 运行绑定契约中已经实例化的适用验证命令；分级超时、前台同步及封闭输入按当前环境落实，不执行模板占位命令。
   - 验证失败：保留真实结果，不登记完成、不推进依赖；普通失败可在当前权限与预算内修复，不无限重试、不降低断言。
   - 超时、取消、缺依赖、零命中、必需项跳过、缺证据或清理未知：进入 BLOCKED，保留成果与全部未完成事项；环境准备与测试分离，不隐式安装依赖。
   - 空输出：按具体操作的必需证据判断，不一律判失败，也不凭静默输出认定业务成功。
   - 验证通过：在唯一任务入口引用真实命令、工作目录、退出状态、关键输出与目标，确认全部适用阶段门禁后才推进；阶段通过不等于全计划完成。

## 4. 完工门禁：对账、溯源与绑定式归档

仅获准实施且全部必需验收通过的任务进入完工闭环；只读任务不进入此流程。

1. **状态对账**：按照 `state-reconcile.md` 对照实现差异、验证输出及架构边界。记录命令、工作目录、退出状态、关键输出与目标；条件一致不能豁免未通过的必需门禁。
2. **ADR 转正**：仅绑定计划要求关联 ADR、全部必需门禁通过且取得转正授权时，将对应提案更新为 ACCEPTED。必需目标版本或运行时证据缺失时保持 PROPOSED，披露阻塞，不转正其他任务的 ADR。
3. **事实更新**：仅获相应写入授权时登记已经验证的事实及真实溯源；未知会话标识保持未知，不编造，不将静态测试外推为运行时事实。阶段交付不自动更新事实基线。
4. **绑定式归档**：仅全计划完成且获准归档时处理实际绑定的活动计划，不固定清空默认暂存路径。目标包含时间和计划标识且禁止覆盖；确认目标完整保存后，再复核源标识与内容版本并处理活动副本，失败或源已变化则保留源。历史输入、其他暂停任务及无绑定计划的轻量任务不参与归档。

## 5. Terminal Execution Penta-Invariants

每条命令遵循当前平台实际支持的终端五大守恒铁律，不照搬其他平台的专用参数：
- **单飞排队**：取得前序命令真实退出回执后才启动下一条；工具提前返回不等于退出，不并发命令，不遗留孤儿任务。
- **分级超时**：探测 15s、验证 30s、构建 600s；使用进程级超时，不能把工具提前返回时间当作进程终止保证。
- **前台同步**：等待真实退出结果，不启动未托管后台进程。
- **输入封闭**：附加 `< /dev/null`，仅选用当前命令实际支持的非交互参数。
- **工具正交**：文件读写使用原生工具；复杂排查脚本先写入项目内草稿区，再限时调用。
