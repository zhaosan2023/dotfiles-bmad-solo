# 可分发治理契约

本文件为棕地治理规程提供套件内可定位的公共依据，避免安装后依赖方法论源码仓库的目录层级。
它定义目标项目候选的最小治理义务，不复制当前仓库的历史材料、任务流水、事实基线或认证声明。
规范可读、套件分发和文档保存不增加操作权限，也不证明引擎、控制器或宿主已经可用。

## 1. 目标项目与套件来源分离

- 套件内规程、模板与本契约按其文件位置解析；目标产物路径按获准目标项目根目录解析，两类路径不得混用。
- 目标逻辑槽位包括 `AGENTS.md`、`specs/governance/`、业务领域 `specs/`、`specs/tasks/`、`docs/adrs/`、`docs/analysis/` 和 `docs/project-context.md`；槽位名称不是这些文件已经存在的证据。
- 目标项目既有宪法、领域契约、已接受决策及显式任务绑定优先；冲突先定位来源并取得必要裁决，不用全局方法论覆盖私有规范。
- 初始化需要当前明确授权：源码扫描、候选写入、正式发布、事实登记、宿主配置和历史迁移分别判断，不从安装许可推导项目写入许可。
- 目标没有治理模块且允许生成候选时，以本文件的公共义务结合目标事实形成领域文档，标明来源、状态与未知；不把本文件或其他仓库的全文直接当成项目事实。
- 已有模块只做获准的定向适配；保护未提交改动、原始证据和其他任务，不整目录覆盖或顺带删除历史资产。

## 2. 业务流与 Plan–Act 职责

1. 从客户结果、授权范围和验收开始，按下一项动作选择最小充分职责切片。
2. Analyst 定位目标、证据与关键未知；Architect 处理必要接口、不变量和取舍；Coder 生产获准候选；Supervisor 审查当前候选与父目标。
3. 四种职责不要求四个进程、固定会议或全套轮询；明确需求和充分获准方案直接消费，不重复完整分析。
4. 只读任务仅取证与会话交付，不写文件、不运行验证、不转正或归档；分析角色不使用终端、不创建或执行探针。
5. 缺权限、必需输入或实际能力时只阻塞相关动作；明确暂停保留全部未完成事项，不恢复其他任务。
6. 模式切换、技能调用、交接和草稿位置不构成额外授权、执行隔离或任务接受。

## 3. 任务贡献契约与单焦点

- 新任务仅在获准持久结晶时参考[套件任务模板](templates/task-unit.template.md:1)，填写真实父目标、范围、输入、产物、贡献标准、逐项验证、审查及授权。
- 任务身份、实例、契约与候选版本分别绑定；未知会话、审查身份和批准来源保持 null，不编造来源或继承历史绿灯。
- 显式 Task Unit 或计划优先，不静默替换；没有显式路径时检查目标单焦点入口，明确空闲不接管其他任务。
- 新入口损坏、引用缺失或身份不一致时阻塞，不静默降级；只有新入口不存在时才兼容发现相关旧计划，缺默认入口是正常状态。
- 薄指针只定位一个任务身份与契约，不保存进度或批准实施；已有焦点不得重置，历史恢复须授权并建立保留来源的新实例。
- 当前进度只来自已核验且覆盖本任务的控制器任务记录；未覆盖时临时引用平台任务记录和真实回执，明确程序强制与防篡改缺口。
- 计划与 ADR 保存契约和决策，不镜像逐轮流水；边界快照不能替代当前权威判定，不另建进度账本。
- 接管、契约变化及阶段边界核对绑定，不逐修改手工同步指纹。阶段通过不等于父目标或全计划完成。

## 4. 最小充分交接与无损背压

- 交接保留当前目标、授权、任务与候选身份、相关差异、验收、必要输入、限制、拒绝项、全部未完成义务和原始证据定位。
- 先保护必需不变量、必要调用边及其支持闭包，再确定性去重和无损编码；不删条件、否定、所有权或副作用来满足篇幅。
- 不广播内部推理过程、无关历史和全部日志；完整原件保留在获准工作区，摘要、索引和指针不替代必需内容的完整消费。
- 接管视图以 80 行、8192 个 UTF-8 字节为默认规划目标，活动切片以 16384 字节为默认目标；这些不是 token 等价或实际硬能力保证。
- 32 块及旧正文、骨架、帧预算不得淘汰新版必需内容；新策略显式启用，不静默改变旧协议。
- 纯软超限只产生去重的结构化 Warning；保留运行身份、阶段耗时、唯一正文块数、正文/核心/编码字节、单帧及累计字节、目标、能力、策略和结果遥测。
- 双方实际声明协议、输入、解码、单帧及累计硬能力和能力来源；优先协商大帧，否则采用已声明分页调用或通知，不追加未声明最终响应。
- 清单与每片绑定同一项目、快照、契约、包身份、编码、序号、精确字节及摘要；消费者独立核对片数、总长度、身份和支持闭包后才确认完整交付。
- 缺片、篡改、混合快照、断管、未协商能力、真实硬能力不足或必需信息缺失进入相关 BLOCKED；分片不扩大外发范围、模型输入能力、请求数或时限。

## 5. CS、SR 与证据失效

- CS 是贡献规格的完整判定，不仅是命令退出零；SR 是满足所需独立性和批准范围的监督审查，两者均满足且版本适用才接受指定贡献。
- 棕地保真门禁分别预先固定非空的必需不变量、必要调用边和支持闭包集合，三者覆盖率均为 100%；不得缩减分母或用空集默认通过。
- 动态、未消歧或语法覆盖不足保留调用点、未知原因及影响；引用存在、表达式计数和文件保存不证明强语义义务已经满足。
- 机械证据引用真实操作或命令、工作目录、当前环境、实际退出、关键输出、原始回执和必需遥测；未运行、帮助输出和历史通过均不能替代当前验收。
- Supervisor 身份、来源、权限、独立性、当前候选及审查原件必须可定位；默认要求 separate_actor 的契约不能静默降为 context_only，同会话换角色自审不构成独立批准。
- 没有实际认证机制时只称可审计审查记录，不宣称密码学签章、防篡改、宿主权限隔离或所有工具旁路已受控。
- 普通失败可在权限和预算内定向修复，但失败不推进依赖；超时、缺依赖、零命中、必需项跳过、来源变化、缺证据或适用清理未知进入相关 BLOCKED。
- 测试必须非零收集且必需项不跳过；文档差异审查等非测试的收集数可以为 null，空输出按具体操作的必需证据判断。
- 候选、实现、测试、契约或环境变化使受影响证据失效，只重验相应证据；保存进度不触发业务重测。
- 审查通过只接受指定贡献，不自动批准正式发布、全局部署、事实登记、ADR 转正、提交、推送或归档。

## 6. 宿主、离线引擎与项目文档边界

- Roo、Cline、Gemini 分别按真实目标版本的规则、技能、配置发现路径和模式信号适配；不能把一个宿主的 YAML 或目录当成其他宿主的有效接口。
- 静态结构、隔离磁盘分发、实际加载、模式职责、程序拒绝及业务验收是不同证据层，前一层通过不证明后一层通过。
- 技能不可用时可以在实际读取权限内显式加载套件材料，但须说明这是读取退路，不是自动技能绑定已经验收。
- solo-distill-mcp 的版本、真实注册或获准 CLI、工具声明、参数、语言覆盖、完整正文、拓扑、消费者与分片能力从当前实现核对，不预造入口或参数。
- 离线扫描不执行目标代码、不导入项目模块、不构建、不联网、不隐式安装依赖；依赖外部模型或服务的能力另判断外发与执行授权。
- 控制器可用且覆盖当前操作时使用获准的类型化入口；否则使用既有获准命令并披露缺口，不把提示词或帮助输出当作控制器验收。
- 获准工程命令串行、前台同步、封闭标准输入，探测、验证、构建分别采用 15、30、600 秒进程级超时及必要强杀宽限；工具提前返回不等于进程结束。
- 安装方法论只部署获准公共资产，不自动生成目标私有治理文档、执行扫描、启动宿主或模型任务；项目文档仅由另获准的治理流程生成候选。

## 7. 候选发布与闭环保护

1. 最高宪法候选少于 150 行，保留公共纪律、最小环境指令、架构底线、领域导航和证据等级；领域模块至少包含不变量、接口/类型边界与验证要求。
2. 源码结构只能支持“采用了什么”，不能单独证明历史动机；有来源的决策形成 PROPOSED ADR，假设和尽调归分析，不编造文件充数。
3. 事实基线读取优先采用目标已声明的新位置，仅其不存在时兼容旧位置；来源冲突、损坏或拒绝不静默换源，事实写入另获授权。
4. 候选输出与正式发布分开授权；正式写入须当前必需 CS/SR 与发布授权，逐目标保护原件并取得成功回执，不承诺多文件整体原子性。
5. 只有关联契约要求、全部必需门禁通过且取得转正授权才接受对应 ADR；缺必需运行时证据继续保持 PROPOSED。
6. 只有整项绑定任务完成且获准归档才处理源；目标不得覆盖，完整保存后复核源身份及内容版本，失败或源变化保留源。
7. 无绑定计划的轻量任务、治理领域规范和其他历史输入不参与任务归档；交付明确实际差异、适用证据、覆盖缺口及未完成事项。
