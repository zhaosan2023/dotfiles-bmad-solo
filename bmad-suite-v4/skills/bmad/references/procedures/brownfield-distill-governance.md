# 棕地项目知识蒸馏与治理归位规程

本规程将源码事实结晶为治理文档，不改变目标项目业务逻辑或 BMAD-Solo 的 Plan–Act、3+1、CS/SR、证据纪律与无损蒸馏。
“初始化目录”“棕地治理”“init-governance”仅短路冗余分析，不能短路授权、身份核验、必需证据或独立审查。

## 前置条件

1. 识别目标棕地仓库、当前实际工作区、输入快照、语言及排除范围；路径来自授权与真实工具，不从打开的标签页推断跨仓库权限。
2. 确认源码及存量资料的只读权限：扫描不得执行目标代码、导入项目模块、触发构建、联网或写回源仓库。
3. 分开确认文档候选输出区的写入授权与正式目录发布授权，列明允许路径、保护资产、回滚范围及验收；只读意图停留在取证与会话交付，不运行验证或落盘。
4. 按实际权限读取目标项目宪法、治理索引、领域规范、相关配置和当前差异；显式任务优先，不接管无关默认计划，不恢复历史任务。
5. 核对离线引擎 solo-distill-mcp 的实际可用性：真实注册或获准 CLI、版本、工具声明、参数模式、AST 语言覆盖、正文与拓扑提取、消费者认证、遥测和分片能力。
6. 入口存在、帮助输出或历史通过不等于本次可用；能力未经核验标记 UNKNOWN，必需入口缺失标记 UNAVAILABLE，阻塞依赖它的实跑，不阻止独立获准的规程编写。
7. 离线模式不得隐式使用网关、模型、下载或依赖安装；若某能力依赖外部服务，只暂停该能力，明确范围和外发授权后再处理。
8. 预先确定贡献标准、非空必需不变量集合、必要调用边集合及其支持闭包，指定独立 SR 主体、身份来源与批准权限；生成侧不得读取冻结评价答案来调优。

控制器真实可用且覆盖本任务时使用其类型化入口及权威任务记录；否则披露缺口，临时引用平台真实回执，不另建运行账本。
目标仓库超出当前客户端边界时须在获准目标工作区接管，不用父目录、软链接或终端绕过权限。

## 执行步骤

下列步骤是获准执行时的操作契约，不是本次已经执行的记录。Step 1 的完整输入是后续文档生成的前置；步骤输出先为候选，正式消费与发布受双门禁约束。
原生文件工具负责助手读写；已获准的引擎输出程序仅能写明确候选区，不能顺带覆盖正式资产。

### Step 1：无损 AST 扫描与拓扑提取

1. 依据核验后的实际工具声明，调用 solo-distill-mcp 的离线扫描、语法单元/完整正文读取、拓扑与来源封存能力；入口名称与参数从当前实现读取，不生成占位调用。
2. 绑定仓库、输入快照、扫描范围和契约版本；完整登记模块、定义、顶层装配、条件分支、接口、数据所有权及副作用边界。
3. 提取必需业务不变量、已知必要调用边及传递支持闭包；动态或未消歧调用保留调用点和未知原因，不将调用表达式数当作已解析边数。
4. 先保护所有必需内容，再确定性去重、共享引用和无损编码；不得截断巨大定义、删除否定或条件、按度数或预算淘汰必需支持。
5. 显式启用兼容的新背压策略。32 块及旧正文/骨架/帧目标是软规划观测，不隐式改变旧协议行为；纯软超限产生去重 Warning，不以超限判失败。
6. 核对双方声明的协议、大帧/分片、单帧与累计字节、输入与解码硬能力及来源；未知不当作无限。优先协商大帧，否则使用已声明分页调用或通知，不向同一请求追加未声明最终响应。
7. 分片清单及每片绑定项目、快照、契约、包身份、编码、序号、精确字节与摘要；消费者独立核对总片数、总长度、整体身份及闭包后确认完整交付。
8. 保留真实运行身份、阶段耗时、唯一正文块数、正文/核心/编码字节、单帧与累计字节、目标、能力、告警、策略及结果遥测；未取得消费回执不宣称完成。
9. 源变化、缺片、篡改、混合快照、解码异常、断管、硬截止、取消、权限拒绝或必需内容缺失进入相关 BLOCKED；分片不扩大模型输入、外发范围、请求数或时限。

出口：完整扫描及来源包可定位，三个必需集合逐项核对，未知和限制保留；仅指针保存或生产者发送成功不满足完整消费条件。

### Step 2：生成项目最高宪法

1. 从源码、构建配置、测试声明和已有规范提取可定位的构建入口、测试入口、架构底线及保护资产；源码事实不自动变成历史动机或业务正确性证明。
2. 在获准候选区生成目标项目的最高宪法，正式槽位为 [`AGENTS.md`](../../../../../AGENTS.md)；目标项目路径统一按目标根目录解析。
3. 保持少于 150 行，正文仅承载公共纪律、最小环境指令、架构底线、领域导航及证据等级；超过时将细节分流领域模块，不删必需义务。
4. 区分命令“源码声明存在”“当前环境可用”“本次执行通过”；未运行不写全绿，缺依赖与未知显式保留，不为补齐模板虚构命令。
5. 保留 Plan–Act、3+1、CS/SR 与当前授权边界；Base 契约由项目宪法与治理领域共同构成，不复制整份规程、流水、凭据或历史任务。
6. 已有项目宪法优先定向合并；用户改动、来源冲突或保护范围不明时停止覆盖，保留原件及候选差异。

出口：行数满足约束、来源可追溯、导航完整；写入候选成功不是正式发布、事实登记或宿主加载证据。

### Step 3：领域模块归位

1. 按真实业务边界生成领域模块，目标槽位为 [`specs/`](../../../../../specs/)下的领域主题文档，不按日期切分领域，也不强求固定模块数量。
2. 每个模块至少包含业务不变量、接口与类型边界、验证断言/要求；补充必要条件、所有权、副作用、支持来源、未知及适用范围。
3. 验证要求引用目标现有真实入口及断言，说明环境、影响范围、入口状态与停止条件；目录初始化不自动执行目标业务测试或创建缺陷回归代码。
4. 将公共治理独立归入 [`specs/governance/`](../../../../../specs/governance/)，保持索引及 01—05 模块职责；业务领域不复制任务账本或整份治理正文。
5. 目标没有治理模块且已获文档写入授权时，基于获准的 Base 规范形成带来源和状态的候选模块；已有模块定向合并，不整目录覆盖，也不将 PROPOSED 自动转正。
6. 稳定知识与候选假设分开；公共规范正式入库须当前双门禁及相应写入授权。仅整理文档不得登记未经验证的运行事实。

出口：领域、治理、任务生命周期分离，接口和验证断言逐项有支持；计划与 ADR 不保存逐轮流水。

### Step 4：历史决策与尽调资产沉淀

1. 有可审计来源支持的历史选择形成候选决策，输出到 [`docs/adrs/`](../../../../../docs/adrs/)，保留原始来源、条件、证据等级和限制。
2. 结构能证明“采用了什么”，不能单独证明“为什么”；无法证实的动机、尽调、反向审查与风险输出到 [`docs/analysis/`](../../../../../docs/analysis/)。
3. 新候选 ADR 默认 PROPOSED；既有 ACCEPTED 记录保持原接受语境，不凭生成文档继承或伪造批准。
4. 领域模块仅引用相关决策和简要适用结论，不嵌入全量决策日志；原始扫描、失败证据和审查材料保持独立。
5. 只有绑定契约要求、全部必需门禁通过并取得转正授权时处理对应提案；目录初始化不自动归档历史任务或登记项目事实基线。

出口：事实、决策、假设和未知分层，决策来源可复读；没有历史决策证据时明确无可结晶决策，不编造文件充数。

### Step 5：任务入口初始化

仅在目标入口不存在且已获创建授权时生成以下空闲薄指针；正式槽位为 [`specs/tasks/_active.md`](../../../../../specs/tasks/_active.md)。
已有入口即使为空闲也先核对来源；非空焦点不能重置，不接管未获准任务，不同时启用新旧权威入口。

```yaml
---
schema_version: "1.0-draft"
active_task_id: null
instance_id: null
task_ref: null
contract_version: null
authority_ref: null
---
```

真实初始化授权来源可定位时填写 authority_ref，未知保持 null；其他身份和任务引用初始均为 null。
薄指针不保存进度、CS/SR 快照或第二份清单；初始化不建立虚构任务，不绑定本次蒸馏为业务执行焦点。
后续第一项业务实施另获授权后，按目标贡献契约实例化任务并绑定焦点；旧任务消费者迁移另获清单授权。

## 质量与安全门禁

### CS：机械证据提取与保真检查

- 冻结项目、范围、输入快照、契约及当前候选；必需不变量、必要调用边及支持闭包集合分别预先固定且非空，三者覆盖率均为 100%，不削减分母。
- 目标确无可实例化必要调用边时先报告适用性缺口并请求契约裁决，不用空集“100%”满足原门禁。
- 核对语法覆盖、完整正文、来源身份、条件、否定、所有权、副作用及全部未完成义务；未知动态边不得伪称已满足强语义义务。
- 保留真实操作或命令、工作目录、版本/环境、实际退出、关键输出、原始回执、必需遥测及消费者认证；测试须非零收集且必需项不跳过，文档审查收集数可为 null。
- 文档验收包括最高宪法少于 150 行、领域三要素、正规化路径与引用、候选状态、空闲指针及既有资产保护；保存成功不替代内容判定。
- 超时、缺依赖、零命中、必需项跳过、来源变化、缺证据或适用清理未知进入相关 BLOCKED；普通失败可在权限与预算内定向修复，不降低断言、不推进依赖。
- 治理初始化按 ops 做差异、文档契约及必要配置语法检查，不运行无关业务单测；扫描引擎运行验收与文档保存分别报告。

### SR：独立性与防篡改检查

- 由契约指定的真实独立审查主体核对当前候选、父目标、CS 覆盖、原始来源与回执、保护资产及发布范围；默认 separate_actor，不能静默降为 context_only。
- 身份、身份来源、批准权限、契约/候选版本及审查原件缺失时 SR 保持 UNKNOWN/BLOCKED，生产者不得冒写 APPROVED 或替代签章。
- 独立消费者/审查者复核来源、完整性摘要和支持闭包，不单凭生成器自认证；生成侧与独立评价侧不得共享可修改的冻结答案。
- 角色换名、同账号可写摘要或提示词切换不证明独立认证、防篡改或隔离；没有真实认证机制时只称可审计审查记录，明确强保障缺口。
- CS=PASS 且 SR=APPROVED、版本适用并满足父目标与授权，才接受贡献和释放指定依赖；审查通过不自动授权发布、转正、部署或归档。

### 回滚与发布保护

1. 源仓库保持只读，候选先写获准隔离输出区；草稿目录不是执行级沙箱，输出程序不得穿越路径或符号链接写入范围外资产。
2. 发布前列明每个新增/合并目标、来源、允许差异及原件保全方式；保护未提交改动和原始失败回执，不自动修改忽略规则来隐藏资产。
3. 正式写入须双门禁及发布授权；逐文件成功回执后复读完整性。多文件操作不承诺整体原子性，失败保留原件和部分完成定位。
4. 外部内容或候选身份变化先停止对账，仅撤回本任务获准且确认未被别人修改的差异；无可靠保全或恢复结果未知时阻塞，不全库重置或整目录删除。
5. 明确暂停进入 SUSPENDED；阶段通过不代表整项完成。无归档授权不处理源任务，无事实写入授权不更新基线。
6. 接管、契约变化及阶段边界复核绑定；不逐修改手工同步指纹。保存状态不触发业务重测，候选/实现/测试/契约/环境变化只重验受影响证据。
