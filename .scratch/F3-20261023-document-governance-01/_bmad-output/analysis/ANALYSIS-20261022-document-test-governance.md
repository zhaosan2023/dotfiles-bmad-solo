## 2. 三遍阅读与证据分层

### 第一遍：范围、职责和验收

问题是长期资产、临时过程、当前契约和宿主入口职责混用，不是测试文件或日期命名本身有错。研究材料提出的痛点作为用户问题线索；材料中其他私有项目的截图、缺陷和因果推断不外推为本仓库事实。

当前契约要求保留语言封装、回归能力、历史决策、唯一证据和跨宿主接管。成功不能用目录数量、新增测试数量为零或文件数减半定义。

### 第二遍：依据等级

- 用户授权：本轮仅旧任务只读对账及新治理结晶；旧任务条件收尾不能豁免必需验收，冻结与活动入口覆盖未授权。
- 当前源码事实：模式白名单、校验器、测试断言、分发映射及 CI 文本可以定位；不等同于通过或加载。
- 历史摘要：旧计划保存的阶段通过摘要和平台调用标识；未取得原始结果时不能认定已重新核验有效。
- 外部一手资料：本次重新取得 Cline 官方模式概述、HumanLayer 上下文工程文章片段与 Huntley 移植原文开头。仅使用实际返回内容；目标安装版本、具体移植提炼步骤和宿主交互证据仍不充分。此前来源编号和检索预算声明不作为本次证据。
- 逻辑推断：职责分离和保全先行可以降低已识别的覆盖风险；未测量维护成本或模型效果。
- 未知：现有改动与历史回执是否一致、目标宿主实际加载与权限行为、研究中部分作者归因及完整原文。

### 第三遍：虚拟重实现

先切入口会丢失旧任务定位；先移动文件会破坏硬编码路径和测试发现；仅合并测试可能丢断言或白盒访问；仅忽略目录可能屏蔽唯一证据；只放通用入口不能证明宿主自动加载。故先保全与契约适配，再分批迁移，分别验证静态、磁盘分发和真实宿主交互。该推演不是实测。

## 4. 研究材料重新裁决

### 有效方法及归因边界

- 按关注领域组织规范、按需加载，常驻入口只保存导航与稳定操作纪律：作为本项目设计原则采纳，不承诺固定窗口占用或自动加载。
- 上游上下文约束与下游测试、类型检查、静态检查、构建反馈分别设计并组合：作为本项目设计原则采纳。不使用未取得的背压仓库引用证明作者归因或本仓库效果。
- HumanLayer 一手文章将 frequent intentional compaction 描述为在开发过程中有意识地组织提供给模型的上下文。[8] 本项目采纳压缩过程材料、保留当前契约、全部未完成事项、来源与未知的原则；本次片段未核实 Dex Horthy 的完整署名、固定窗口比例、效果或删除要求，不作这些归因。
- 优先复用与内聚已有测试，不要求源码与测试一对一；持久回归与临时验证按用途、断言、缺陷及复现价值分类。
- Huntley 的作者原文开头明确讨论将代码库从一种语言移植到另一种语言。[9] 本次返回片段没有展示测试提炼的完整步骤，该具体方法保持待核验；本提案不以移植方法为删除日常回归的依据。

### 否决、降级及更正

研究输入中固定窗口比例、行数阈值、成功率变化、97/98 分、全部门禁 PASS、100% 加载、“无未知”、测试新增必须为零、源码测试一对一、只保留 ACCEPTED ADR、完成自动改需求及删除计划的说法均不作为当前事实或验收。

Go 测试分类不能将包内部未导出成员与 internal 目录导入范围混为同一限制；迁出是否可行须看包、模块、访问及工具链。文件名称带工单号不证明断言无价值，构建标签也不能让包外测试凭空获得未导出成员访问权。本报告不引用未取得的语言官方原文，不宣称已完成跨语言实测。

此前无对应工具结果的引用与检索成功声明撤回。当前 Cline 官方概述将 Plan 定位为不改变文件的探索规划，将 Act 定位为按计划实施。[4] 官方子代理文档另描述 Plan 下无文件编辑工具、拒绝通常改变文件的部分命令。[2] 两份材料范围不同，不足以证明所有入口都禁止命令；目标 IDE 版本、终端限制与实际结果仍待核验。

| 持久测试及夹具 | 复用[`tests/`](../../tests/)与必要同包 Go 测试 | 必需回归随工程版本保留和提交；本仓库 CI 可见，不默认随插件运行分发 |
| 临时工作区 | 过渡[`scratch/`](../scratch/)，后续候选[`.scratch/`](../../.scratch/) | 草稿与一次性探针按任务授权；忽略规则不是权限或证据可信度保证 |
| 持久证据 | 过渡[`verification/`](../verification/)；目标目录暂不迁 | 原始回执可能是一手证据；摘要是解释。先保留来源、适用范围及唯一依赖，再裁决脱敏、同步与保留 |

表中分析目录的过渡位置以本报告所在的现有 analysis 目录为准；不借此创建额外活跃计划。

### 测试治理

1. Python 默认集中，先复用当前测试分组；允许确有语言、工具或项目机制依据的例外，不强迫新建 unit/backpressure 等空层级。
2. Go 白盒测试需访问未导出成员时留在业务包；黑盒与跨组件测试按合法模块、导入及发现机制集中，不为整洁导出内部状态、复制实现或削弱断言。
3. 持久回归按缺陷、契约、不变量及必要 I/O/所有权/锁/恢复边界判定。跨组件安全回放可能同样是持久资产，不能归为一次性垃圾。
4. 临时探针与运行输出分别治理。探针可不提交，但必要发现须形成可复现长期断言或保留唯一来源；原始输出不得混入测试源码目录充当回归。
5. 模块/契约与测试多对多，先复用规范及目录验证入口；无真实检索困难不增加映射文件，不维护第二份状态账本。
6. 优先内聚已有测试，不强制表驱动、源码一对一或单个巨型测试文件；数量减少不是验收，语义、发现和必要边界保留才是。

### 方法论、规范与决策

全局方法论只规定稳定授权、证据和治理原则；项目事实与需求属于项目。助手可以依据证据提出项目需求，不必全部手写，也不必等背压失败后才产生；重大变化由用户确认。动态背压发现不自动升级为全局规则。

领域规范保存当前约束，ADR 保存为什么作出重要取舍。有效既有决策直接引用；只有新取舍才新建提案。测试通过不自动修改需求、接受 ADR 或登记项目事实。

## 7. Cline Plan/Act 与 Roo 薄适配

Cline 官方概述将 Plan 描述为不改变文件的探索与规划，将 Act 描述为按计划实施。[4] 本设计据此默认 Plan 会话分析，文档持久化走单独范围明确、获准的写入步骤，不通过命令绕过编辑限制。当前证据不足以把 Plan 认定为执行级沙箱；目标版本、文件写入接口和终端限制分别待核验。

| 问题 | 当前裁决 | 后续验收 |
|---|---|---|
| Plan 能否原生保存文档 | 未取得目标版本写入接口证据；默认会话交付。保存文档可另通过范围明确的获准写入步骤，不能借终端绕过 | 固定安装版本，核对工具与拒绝/允许回执 |
| Plan 终端是否真正受限 | 当前未取得目标版本工具级终端限制证据；Insufficient evidence，不能判通过或断言具体绕过行为 | 固定目标版本与执行入口，核对源码，再以另获授权的隔离交互验收 |
| 点击 Act 是否授权 | 仅表示能力/交互切换；只有用户批准的具体计划、阶段和范围才构成本项目实施授权 | 记录输入、切换、绑定计划和工具审批；不自动授予安装、迁移、部署、提交 |
| 规则是否自动加载 | 本轮未取得足以确认目标版本规则位置、加载优先级与薄桥接接口的证据；保持待核验，不从文件存在推断加载 | 固定版本与规则位置，确认有效内容与优先级 |
| 技能是否自动调用 | 当前取得的材料不足以确认目标版本技能调用接口、自动触发或模式条件字段；不编造接口 | 设计自然语言入口，但自动发现、加载、调用与行为路由分别验收 |
| 模式条件字段 | 没有取得实际 schema，不提供猜测字段 | 按目标版本一手文档及源码实例化，不预造配置 |
| Roo 权限适配 | 保留现有受限模式；静态白名单及版本执行效果分开 | 获准文档写入、生产/终端拒绝与工程验证分别记录 |

本轮研究基于当前官方材料片段，不绑定未知安装版本，不宣称目标稳定版本已经确认。优先采用单一项目权威内容和薄宿主桥接；旧事实基线只引用、不双写、不在本轮改为根入口。

当前[`源分发器`](../../scripts/deployment_source.py:81)将套件普通文件映射到 Gemini 插件和规则、Roo 规则与显式模式目标，所读取接口未提供 Cline 专用映射。这不足以判断其他途径是否安装或加载 Cline，只能说明不能由此分发链路证明其加载；新增适配必须保留现有所有权、源复核、锁与事务，不复制部署框架。

## 8. DR 反向审查与修订

| 反例 | 必须保留的修订 |
|---|---|
| 旧计划仍阻塞 | 可研究新任务；旧计划保持原状态与入口，新计划采用独立确认路径，不冻结旧义务 |
| 迁移中断或进程状态不明 | 分批出口，保留源、备份和诊断；不能声明全完成 |
| 源内容并发变化 | 入口交接和批次写入前复核，变化停止，不覆盖他人改动 |
| 相对引用失效 | 逐消费者核对引用；获准迁移时保留原字节与原目录语境，不直接执行历史命令；本轮不冻结旧任务 |
| 测试发现或 CI 收集丢失 | 迁移前后比较语义与发现范围；非零不是唯一充分条件，不删必需断言 |
| Go 私有成员访问失败 | 留同包或否决迁出，不导出内部状态与复制实现 |
| 唯一回执误删 | 清理前查引用和唯一依赖，先完整保全；摘要不能替代原始证据 |
| 默认代理误读历史 | 活动入口指向明确，历史默认按需；忽略配置不承诺全部工具隐身 |
| 全局规则污染项目 | 只全局分发方法论，项目需求、证据及私有内容保留项目边界 |
| 宿主规则未加载 | 无法确认则显式读取及人工绑定，保持未知，不由磁盘文件推断加载 |

## 9. 分阶段迁移与独立计划契约

本节是供经确认路径实例化的迁移契约，不是已经保存的新活动计划。复用[`现有计划模板`](../../bmad-suite-v4/skills/bmad/references/templates/implementation-plan.template.md:1)，候选新标识 BMAD-DOCUMENT-TEST-GOVERNANCE-20261022-01；状态 DRAFT、场景 structural、影响 M、会话空值、关联本轮 PROPOSED ADR。没有创建的新验证资产保持待创建，已有入口可用不等于通过。报告保存分析及阶段边界，独立计划以后仅承载执行契约与具体命令，不复制全文研究。

### F0：独立路径确认与契约绑定

- 依赖：用户确认独立计划路径，模式实际允许写入，路径校验支持，且目标不存在或已有内容得到保护。
- 现有[`模式白名单`](../../bmad-suite-v4/roo/settings/custom_modes.yaml:8)没有独立活动计划目录；历史归档目录不能充当未经确认的活动入口。本轮不修改模式配置，不先向未允许目录写入。
- 旧[`活动计划`](../pending_implementation_plan.md:1)与旧[`ADR`](../adrs/ADR-20261021-v4-attended-repair-and-repository-cleanup.md:3)保持不变。新计划明确绑定独立路径，显式路由优先，不读取默认入口来替换新任务。
- 独立计划保存前核对真实模板、关联 ADR、支持字段、验证资产与限时命令；收到成功回执才能列为已保存。
- 无合适路径时先交付报告与提案，计划保存待确认；不通过冻结、改名或腾空旧入口解除阻塞。

### F1：治理契约与路径适配

- 依赖：新计划身份、范围和本阶段工程授权。
- 预期范围：[`分析技能`](../../bmad-suite-v4/skills/ana-solo/SKILL.md)、[`工程技能`](../../bmad-suite-v4/skills/bmad/SKILL.md)、[`DM 参考`](../../bmad-suite-v4/skills/ana-solo/references/decision-matrix.md)、相关共享与 Roo 规则、[`模式配置`](../../bmad-suite-v4/roo/settings/custom_modes.yaml)、[`计划模板`](../../bmad-suite-v4/skills/bmad/references/templates/implementation-plan.template.md)、[`校验器`](../../scripts/validate-roo-contracts.py)及[`README.md`](../../README.md)。
- 相关测试范围：[`规则契约`](../../tests/roo_contracts/)、[`分发回归`](../../tests/roo_distribution/)。按最终改动选用现有断言，必要新行为用例先创建；不固定数量，不盲跑全库。
- 不移动内容先改职责和消费者；新增路径允许范围应精确，不扩分析终端权限。只修改方法论与模板，不将项目规范全局分发。
- 出口：现有入口兼容、拒绝路径和新路径规则有真实相关回执；未知宿主行为不被静态结果替代。

### F2：薄宿主桥接的设计与隔离验证

- 依赖：指定 Cline/Roo 版本、原生规则/技能接口及明确隔离范围；本轮无启动授权。
- 预期范围：仅获准项目内桥接、模板及相关分发消费者。真实全局宿主路径不实例化，不提供猜测 mode 条件字段。
- 验证项目入口单源、规则发现与技能调用分离、Plan 会话分析与获准文档保存分离、Act 绑定具体计划及审批；Roo 保留权限组和受限路径适配。
- 未取得接口则保留方案 A 的显式读取，不创建第二份项目上下文，不用软链接绕过现有物理分发拒绝边界。

### F3：文档、测试和证据的分批迁移

- 依赖：另行生产迁移授权、最终逐文件清单、引用及唯一证据盘点；本轮仅设计。
- 每项清单记录源、目标、用途、必要引用、发现/调用方、所有权、保全方式及失败恢复；不存在的目标标待实现，不虚构全部文件清单。
- 测试优先复用现有集中结构，允许必要 Go 同包；文档逐项分类为当前、历史、被替代或待核验。证据目标未裁决前保持原位。
- 出口：引用与测试发现可用、必要语义和副作用回归保留、跨机器证据策略明确；失败只恢复本批次获准改动，保留其他用户差异，不进行全库恢复。

### F4：明确目标的宿主验收与阶段交付

- 依赖：独立真实宿主授权、目标版本、写入范围和交互入口；不由 Act 点击、安装或重载自动授权。
- 验收：有效规则身份、只读任务无持久写入、获准文档保存、生产与终端拒绝边界、工程验证、第三方资产保留，分别记录输入、请求和实际结果。
- 旧阶段 2 是否可复用新结果必须核对旧目标与验收，不能自动以新任务通过代替旧任务。
- 仅当前全部必需义务有真实证据才交付阶段；新 ADR 接受、事实更新、提交推送及完成归档分别按授权处理。
