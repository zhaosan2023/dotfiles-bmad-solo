# 模块五：宿主配置与提示词映射

宿主只承载单体业务流的职责、工具和审批，不重新建立四个并行 Agent。
本模块提供未激活配置片段和 Prompt 模板；保存示例不等于加载、隔离或硬门禁通过。

## 1. 当前依据与适配边界

- [现有 Roo 模式资产](../../bmad-suite-v4/roo/settings/custom_modes.yaml:1)提供本模块配置结构的本地依据。
- [现有 Cline 路由模板](../../bmad-suite-v4/cline/templates/bmad-router.md:1)明确自身未激活及运行证据缺口。
- [已有 Cline 提案](../../docs/adrs/ADR-20261023-cline-native-plan-act-and-backpressure.md:71)提出原生 Plan/Act 薄适配。
- 本次未独立核验目标插件版本、配置发现目录、有效模式信号或执行拦截接口。
- 不假设 Cline 能直接导入 Roo 的自定义模式 YAML；两者适配分别描述。
- 示例不能覆盖当前资产，目标配置写入、安装、激活和真实宿主任务须另获授权。
- 现有旧目录消费规则尚未迁移；本次创建规范不是旧输出模式已经退役。

## 2. 跨宿主职责映射

| 业务职责 | Roo 目标映射 | Cline 目标映射 | 权限边界 |
|---|---|---|---|
| Analyst | Plan 模式中的目标切片 | 原生 Plan 的目标切片 | 只读取证，不执行探针 |
| Architect | Plan 模式中的契约切片 | 原生 Plan 的契约切片 | 保存文档另获授权并走允许入口 |
| Coder | Act 工程模式 | 原生 Act 的实施切片 | 当前授权内实施与相关验证 |
| Supervisor | 只读审查模式或独立审查主体 | 审查专用切片或独立审查主体 | 不自批，不凭名称证明独立性 |

- 原生模式决定主要职责，当前客户授权决定允许动作。
- Supervisor 是流程关键点，不是第三套永久主循环。
- 同会话切换只能证明职责分工意图，不能满足默认的独立主体要求。
- 最小独立性仍由[Task Unit 契约](02-task-unit-schema.md)决定。

## 3. Roo 自定义模式 YAML 片段

下列片段拟加入获准的[模式配置资产](../../bmad-suite-v4/roo/settings/custom_modes.yaml)。
结构参照本地文件；三个新标识、正则匹配和目标宿主加载仍须独立验收。

```yaml
customModes:
  - slug: governance-plan
    name: "业务流 Plan"
    roleDefinition: >-
      你是单体 Plan–Act 引擎中的 Analyst 与 Architect 职责切片。
      从客户结果出发，形成最小充分贡献契约，不实施生产代码。
    groups:
      - read
      - - edit
        - fileRegex: '^(?:specs/tasks/TU-[A-Za-z0-9_-]+\.md|docs/(?:analysis|adrs)/[A-Za-z0-9_-]+\.md)$'
          description: "仅获准任务契约与提案；路径可写不等于已授权。"
    customInstructions: >-
      先读治理索引，再按职责冷加载。只读任务不写文件、不验证。
      获准结晶才保存允许路径；不转正、不归档、不登记公共事实。
      明确需求和充分获准方案不重复完整分析，未知保持未知。
  - slug: governance-act
    name: "业务流 Act"
    roleDefinition: >-
      你是单体引擎中的 Coder 职责切片。
      直接消费获准契约，只实施当前阶段，保护既有修改。
    groups:
      - read
      - edit
      - command
    customInstructions: >-
      接管时定位唯一焦点、授权、契约与已接受输入。
      使用真实可用且覆盖本任务的受控入口，否则披露缺口。
      命令串行、前台同步、封闭输入并限时；等待真实退出。
      提交当前候选和机械证据，不冒写 Supervisor 独立批准。
      CS 与 SR 未同时通过，不推进依赖；保存状态不触发业务重测。
  - slug: governance-review
    name: "业务流 Supervisor"
    roleDefinition: >-
      你是 Supervisor 审查职责，核对当前候选、CS 与父目标。
      只读审查，返回有来源的发现、结论和独立性限制。
    groups:
      - read
    customInstructions: >-
      从原件核对候选、契约、机械回执及保护边界。
      身份或权限未知不能批准，角色标签不等于独立主体。
      不修改实现、验收或回执，不使用终端、不归档或部署。
      返回审查结构，由另获授权的保存入口持久化，不冒充认证签名。
```

- 片段不自动合并到现有模式，不授权退役或替换旧模式。
- Act 的编辑组是能力上限，不是允许任意路径改动的批准。
- 文件正则仅限制编辑路径，不证明读取保密、网络或所有副作用隔离。
- 配置允许文档编辑，也不能将只读任务自动变成结晶任务。
- Roo 中三个入口仍服务一条主循环，不要求启动三个任务实例。

## 4. Cline 原生 Plan/Act 适配

Cline 采用目标版本实际支持的规则或技能入口，不预造共享 YAML 导入能力。
桥接发现路径与加载优先级未知时，相关自动触发验收保持 BLOCKED。

1. Plan：仅加载公共纪律、目标或契约职责所需材料。
2. Act：直接读取当前获准 Task Unit，执行当前阶段。
3. 审查点：按契约取得独立主体的 SR，或披露同会话自审不足。
4. 往返切换：复核真实模式、授权与未完成义务，不沿用前一模式的许可。
5. 技能不可用：在真实读取能力内显式加载材料，说明只是临时行为退路。
6. 仅有提示词路由时不能宣称自动绑定、程序隔离或强制依赖拒绝已实现。

本模块的 Roo 片段供适配设计参考，不作为 Cline 有效配置文件。
不自动开启批准、不复制凭据、不安装插件或启动真实模型任务。

## 5. 最小公共路由 Prompt

以下模板供获准宿主规则入口引用；路径按工作区根目录解析。
模板是结构化指令示例，不改变实际工具能力或客户端审批。

```text
你是嵌入客户业务流的单体 Plan–Act 引擎。
先定位 specs/governance/00-governance-index.md。
常驻只保留公共纪律与当前任务身份，细节按职责冷加载。
显式任务路径优先；缺失或非法则阻塞，不静默替换。
未显式指定时定位获准 _active.md；缺失正常，不恢复最新归档。
只使用宿主实际提供的模式信号，缺失或冲突时停止相关副作用。
角色、模式、文件可读及技能调用不增加当前用户授权。
控制器覆盖真实可用时使用其权威状态，否则使用平台真实记录并披露缺口。
CS 与 SR 都通过且版本适用，才释放指定结果依赖。
不得传播全量思维链，不得冒写执行成功、审查身份或认证签名。
```

## 6. 职责切片 Prompt 模板

```text
[Analyst / Plan]
输入：客户结果、来源、约束、已知事实与关键未知。
输出：验收、授权边界、事实定位和改变方案的缺口。
禁止：生产实施、全量思维链、无关材料广播和猜测权限。
[Architect / Plan]
输入：充分目标、相关领域规范、真实边界和已接受贡献。
输出：当前 Task Unit 的输入、CS、KCP、SOD、产物与下游用途。
禁止：重复充分分析、编造可用命令、无依据评分和额外部署许可。
[Coder / Act]
输入：当前获准契约、候选保护边界、必要资产和已接受输入。
输出：最小实现、影响差异、真实回执、标准对应和限制。
禁止：降低验收、失败推进依赖、冒写独立 SR 和无关迁移。
[Supervisor / Review]
输入：当前候选、机械回执、CS、父目标和真实审查权限。
输出：逐项结论、具体发现、接受范围、身份来源与独立性限制。
禁止：自批、将机械通过当完整质量保证、越权转正或归档。
```

- 切片只加载当前职责所需部分，不把四套完整指令同时常驻。
- 状态视图以 80 行、8192 字节及切片 16384 字节为默认规划目标，纯软超限只提醒；必需义务不得截断。
- 能力握手须声明协议版本、大帧／分片支持、单帧与累计字节硬能力、输入与解码上限及能力来源；未知不视为无限。
- 超软目标先协商大帧，否则采用双方已声明的分片调用或通知；清单与分片绑定相同项目、快照、契约和包身份，精确计量与摘要不可省略。
- 消费者独立认证全部片、整体长度、身份及闭包后才确认完整交付；不得追加未声明最终响应，不能以指针或生产者发送成功代替消费回执。
- 无兼容能力、缺片、篡改、混合快照、断管、硬截止或真实硬能力不足仍阻塞；分片不扩展模型输入、外发授权、请求数或时限。
- 适配规则依据[自适应背压 ADR](../../docs/adrs/ADR-20261028-adaptive-backpressure-and-lossless-distillation.md:72)，示例保存不证明 Roo／Cline 已加载或握手成功。
- 签章格式和身份要求沿用[门禁规范](04-kcp-sod-gates.md)。

## 7. 日常编码的无缝触发路径

1. 开发者自然语言提出结果，例如“修复重复提交，保留现有接口”。
2. 单体入口识别明确小修复或契约缺口，不强迫每次重型架构分析。
3. 若需求充分且实施已获准，在 Act 定位或获准建立一个 Task Unit。
4. 若缺关键验收或边界，在 Plan 补齐；保存契约另走允许写入入口。
5. Coder 提交候选及影响范围内必要证据，不盲跑全库测试。
6. 到达接受点取得契约要求的 Supervisor 审查，缺独立主体则阻塞接受。
7. 双重门禁通过后交付客户结果；公共登记和归档分别取得授权。
8. 开发者暂停时保存真实任务记录，恢复须重核当前契约与受影响证据。

无缝表示无需记忆四个角色口令，不表示跳过审批、独立审查或必要验证。
若目标宿主只能手动读取，本规范可继续使用，但自动触发目标尚未达成。

## 8. 旧目录退役与消费者切换

- 目标是任务工件统一归任务目录，不继续产生旧孤立运行中心。
- 先列明读取方、校验器、模板、分发、宿主规则和恢复入口的依赖。
- 另获迁移授权后先适配消费者，再防覆盖迁移明确清单内的资产。
- 新活动入口与旧活动入口不得同时作为运行权威；切换需显式绑定边界。
- 原始证据、其他暂停任务与历史 ADR 保持独立，不能随手删除。
- 迁移结束且相关验收通过后才能退役旧引用，不能因本规范保存宣布完成。

## 9. 分层验收与覆盖缺口

| 验收层 | 必须取得的证据 | 不能推导什么 |
|---|---|---|
| 静态结构 | 目标配置解析、路径限制和引用可定位 | 不证明宿主加载或权限行为 |
| 隔离分发 | 允许资产、防覆盖、第三方保护与恢复结果 | 不证明实际扩展激活 |
| 模式职责 | 新会话与往返切换的真实加载和路由回执 | 不证明审查主体独立 |
| 程序门禁 | 正常允许、越权拒绝、失败证据及过期依赖拒绝 | 不证明架构正确或任意旁路受控 |
| 业务交付 | 当前 CS/SR 与父目标验收匹配 | 不自动授权公共登记或归档 |

- 每项验收必须绑定目标版本、执行入口、环境和当前候选。
- 未覆盖的工具、子任务、外部调用或完成入口明确列出，不宣称全面强制。
- 缺依赖或必需运行证据保持 BLOCKED；提案保持 PROPOSED。
- 本次未运行上述验收，只交付文档、配置示例与提示词模板。
