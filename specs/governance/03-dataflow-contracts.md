# 模块三：环节间“刚刚好”数据交接契约

数据是流程中流动的信息，交接质量以能否满足下游作业为准。
传递可审计结果、必要证据、限制与使用条件，不广播全量思维链。

## 1. 原则与来源

- [业务数据依据](../../docs/Ralph-Wiggum-Loop/service-process-IT-quality-engage.md:33)要求信息不冗余、不缺失。
- [贡献交接依据](../../docs/Ralph-Wiggum-Loop/autoswarm.md:153)将范围、结果、证据与下游用途关联。
- 最小不是最短：缺少验收、权限或风险的摘要不合格。
- 充分不是全量：探索过程、重复日志和内部推理不应成为载荷。
- 下游消费条件在上游开始作业前定义，不在交付时临时猜测。
- 信息流通与依赖释放不同，收到信息不等于贡献已接受。
- 公共规范只吸收稳定且获准登记的结论，不吸收全部任务材料。

## 2. 标准交接矩阵

| 交接方向 | 必须输出 | 严禁输出 | 消费条件 |
|---|---|---|---|
| Analyst → Architect | 客户目标、验收、事实来源、约束、关键未知 | 全量检索记录、内部思维链、无关历史、未经授权的实施命令 | 目标可追溯，事实与假设分开，关键缺口明确 |
| Architect → Coder | 获准贡献范围、接口、不变量、输入、CS、验证及停止条件 | 重复充分分析、无依据评分、无限方案树、额外部署许可 | 当前契约充分，必要输入已接受，实际执行获准 |
| Coder → Supervisor | 当前候选、影响差异、真实回执、标准对应、限制与失败定位 | 自批签章、编造通过、只报测试数量、掩盖跳过或过期结果 | 候选与证据可定位，审查者能独立核对 |
| Supervisor → 公共 Specs | 双重接受结论、稳定不变量、接口变化、必要 ADR 引用及登记授权 | 全部审查对话、临时补丁、调试流水、未接受假设 | 必需门禁通过且取得公共规范写入授权 |
| Supervisor → Coder | 具体驳回项、对应标准、证据缺口、允许修正范围 | 模糊否定、擅改低验收、越权修复命令 | 保留原候选，修正范围在授权和预算内 |

四类角色不是固定部门接力赛，所有输出始终关联同一客户父目标。
小修复可合并前两个职责，但不能省略必要输入、验证和审查条件。

## 3. 公共交接信封

交接信封可以由宿主消息承载，不要求每个环节新建物理文件。
若须持久化，须明确资产位置和授权，不能形成第二份进度账本。

```yaml
schema_version: "1.0-draft"
handoff_id: null
task_id: DEMO-001
instance_id: null
contract_version: "1"
candidate_version: null
producer_role: Analyst
consumer_role: Architect
intent: contribution_submission
parent_objective_ref: null
artifact_refs: []
evidence_refs: []
criterion_refs: []
assumptions: []
limitations: []
consumption_condition: ACCEPTED_CURRENT
acceptance_authority_ref: null
required_response: false
response_to: null
next_action: null
```

- 标识、版本与来源必须对应当前 Task Unit，缺失不能用旧摘要补齐。
- 工件引用包括位置、相关范围及受控版本，不把聊天措辞当内容身份。
- 证据引用指向原始回执及判定入口，保留运行环境和适用候选。
- 必要未知列为限制，不能通过删字段伪造闭合交接。
- 交接信封只是信息载体，不自行批准贡献或释放依赖。
- 身份和权威引用未知时保持 null，相关批准不能成立。

## 4. Analyst 的入口输出

### 必须输出

- 客户要获得的结果、价值与验收者，而非仅描述内部工作步骤。
- 需求来源、事实来源及能够复读的范围定位。
- 业务限制、允许操作、保护资产及不在本次范围内的事项。
- 影响实现决策的未知，以及最短补证或澄清路径。
- 已有充分方案的定位，避免下游重复完整分析。

### 禁止输出

- 原始阅读材料的全集、与当前客户结果无关的资料摘要。
- 隐含的生产写入许可、猜测的会话身份或宿主能力。
- 没有证据的性能、成本或质量保证。
- 私密信息、凭据正文及内部详细推理过程。

### 出口判定

目标、验收和来源足以支持下一项架构判断，才完成本职责贡献。
关键未知仍会改变下游方案时，阻塞对应决策，不扩大调查范围。

## 5. Architect 的契约输出

### 必须输出

- 最小连贯贡献范围及父目标映射，列出必要依赖而非任意角色拆分。
- 公共接口、不变量、数据所有权与副作用边界。
- 产物形态、下游用途、CS 标准及必要证据。
- 验证环境前提、入口就绪状态、预算与停止条件。
- 重要决策的简要依据；契约要求 ADR 时引用对应提案。

### 禁止输出

- 所有候选方案的思维链或未经裁决的分支树。
- 为模板整齐而编造命令、测试编号或可用依赖。
- 与当前贡献无关的架构重构、部署和目录迁移。
- 将 PROPOSED 决策写成已接受事实。

### 出口判定

Coder 能依据契约执行而不必重新猜测目标、允许路径或验收。
命令尚未创建时标记不可用，并阻塞依赖该命令的验证，不阻塞无关文档。

## 6. Coder 的候选输出

### 必须输出

- 当前候选工件定位、变更范围与必要调用方影响。
- CS 各项对应的结果或明确未满足项。
- 真实命令或受控操作、工作目录、退出状态、关键输出与原始证据。
- 超时、零命中、必需项跳过、清理状态与环境差异。
- 对下游用途仍有影响的限制、风险和未完成义务来源。

### 禁止输出

- 仅写“完成”“全绿”而没有目标和证据。
- 使用旧候选通过回执、帮助命令或日志保存成功代替本次验证。
- 合并成功与失败运行、隐藏必要项未执行的事实。
- 自行补写 Supervisor 批准或认证身份。

### 出口判定

候选提交不等于接受；只提供完整审查包，等待独立 SR 结论。
保存结果可以成功，而任务仍因必需验证缺失保持 BLOCKED。

## 7. Supervisor 的接受输出

### 必须输出

- 审查主体及身份来源、独立性等级、批准权限边界。
- 当前任务、契约、候选及机械回执引用。
- 对 CS、父目标、影响边界和证据适用性的逐项结论。
- 拒绝或接受理由的简要审计依据，不披露内部推理过程。
- 下游允许消费的具体输出与保留限制。

### 禁止输出

- 生产者自行冒写的批准、无来源的“独立审查”声明。
- 用机械通过替代语义适配，用语义认可替代缺失运行证据。
- 把批准贡献扩大为允许部署、转正 ADR 或写入公共规范。
- 将终止、失败或取消的贡献写成成功输入。

### 出口判定

接受条件以[模块四](04-kcp-sod-gates.md)的 CS/SR 合取和版本适用性为准。
同会话角色自审不足以满足独立主体要求时保留相应 BLOCKED。

## 8. 公共领域规范的入库载荷

- 当前稳定的业务不变量与接口定义，不复制整个 Task Unit。
- 必要的验证要求、环境约束和职责边界。
- 经批准的重要决策来源，以及仍适用的条件和限制。
- 当前有效知识替代关系，防止旧结论与新规范同时被消费。
- 获准写入的事实附真实来源，未经验证的设计继续标为提案。

公共规范不保存每轮工具调用、重试次数、日志全集或活动进度。
入库授权不等于归档授权；两个动作分别判断。

## 9. 缺口、修正与等待

1. 接收方核对必需字段、版本、工件可读性与消费条件。
2. 不满足时给出具体缺口、影响标准、责任角色及解除条件。
3. 保留已有候选与证据，不要求无差别重做上游全部工作。
4. 必需回复绑定受影响动作，不能用“已收到”替代问题答复。
5. 检查循环等待；不能让被请求方先依赖当前尚未接受贡献。
6. 超时保留未答问题，交 Supervisor 处理，不把缺失输入设为接受。
7. 在当前授权内继续无依赖且资源边界明确的事项，不并发终端。

## 10. 先保真后压缩与协商交付

- 沿用[模块一预算](01-plan-act-role-embedding.md:118)：80 行、8192 字节接管视图及 16384 字节切片是默认规划目标，不等同 token 或硬能力上限。
- 先完整登记不变量、必要调用边、支持闭包、未完成义务、限制、拒绝项与版本，再去重和无损压缩；不得为 32 块或旧 22,016 字节目标删除必需内容。
- 纯软目标超限产生结构化 Warning，并保留完整预算遥测；不是交接失败。
- 超限触发双方显式大帧能力协商；不支持大帧时用已声明的分片调用或通知，不为同一请求追加未声明的最终响应。
- 清单与每片绑定项目、快照、契约、包身份、编码、序号、字节和摘要；消费者独立核对总片数、总长度、整体身份及支持闭包后才接受。
- 索引与指针仅用于定位，必需原件尚未获取并认证时不算完整消费；缺片、篡改、混合快照、断管或实际硬能力不足保持 BLOCKED／拒绝。
- 分片不增加模型输入能力、外发范围、请求数或时限；清洗上下文不删除原始资产，物理清理另获授权。

## 11. 验收与反例

- 正例：下游能定位当前候选、验收和来源，不必重读整个历史。
- 缺失反例：只有代码差异，无验收与回执，不能进入正式消费。
- 冗余反例：广播全部探索和角色聊天，违反最小充分交接。
- 失效反例：契约更新后继续引用旧批准，必须重审受影响证据。
- 越权反例：Supervisor 接受贡献后自动部署，批准范围不匹配。
- 伪独立反例：Coder 换角色名称自签，不能宣称强 SOD。

本模块只规定交接契约，不证明自动组装、控制器校验或宿主消息接口已实现。
