## 3. 纲领目标

- 业务流是客观原点，工具、角色和目录必须服务客户可验收价值。
- BMAD-Solo 是单体通用 Plan–Act 引擎，不以增加 Agent 数量作为治理目标。
- 角色是流程中的职责切片，不是强制独立进程或组织部门。
- Task Unit 是连接目标、贡献、验收、依赖和责任的基本单元。
- 每次交接只传递下游需要的结果、依据、限制与使用条件。
- 质量与内控构筑在实际执行和依赖释放边界，不作为结束后的附加表演。
- 贡献规格 CS 与监督审查 SR 都必须满足，才能释放下游依赖。
- 任务工件向统一任务目录收敛，消除孤立输出目录作为长期运行中心的模式。
- 目录整齐不优先于用户资产保护、真实权限与可追溯证据。

## 5. 全局对象与职责

| 对象 | 应保存什么 | 不应保存什么 |
|---|---|---|
| 客户目标 | 价值结果、验收标准、授权边界 | 角色表现排名、内部聊天长度 |
| Task Unit | 贡献契约、输入条件、责任、证据引用 | 全量思维链、逐轮聊天转录 |
| 活动入口 | 唯一焦点的身份与定位 | 重复的完整任务正文、第二份进度 |
| 公共领域规范 | 当前有效不变量、接口、验证要求 | 调试流水、未经接受的候选结论 |
| ADR | 重要决策、依据、条件与状态 | 每轮执行日志、编造通过记录 |
| 验证回执 | 当前候选的真实结果与适用范围 | 模型自行补写的成功判断 |
| 审查签章 | 独立审查依据、结论、限制与身份来源 | 由生产者冒写的批准 |

## 6. 全局不变量

1. 所有任务必须能追溯到一个明确的父目标或客户需求。
2. 同一会话只能有一个正在执行副作用操作的任务焦点。
3. 未被接受的结果可以辅助诊断，但不能充当正式下游前置输入。
4. 完工、取消、失败是不同事实；终止不等于成功接受。
5. 模式、角色名称和阅读计划都不增加实际操作权限。
6. 契约、候选、测试或验证环境变化使受影响证据失效。
7. 仅保存状态不会引起业务重测；只重验受影响的证据。
8. 缺依赖、超时、必要输出缺失与未知清理结果不得记为通过。
9. 未完成事项必须全部保留；默认规划目标越界只提醒并协商大帧或分片，实际硬能力不足或必需信息缺失才阻塞交接。
10. 归档或公共规范入库必须取得相应授权，不因文件已保存自动执行。

## 7. 生命周期纲要

- INTAKE：核对意图、范围、依赖、模式与真实工具权限。
- READ_ONLY：只取证与会话交付，不写文件、不运行验证。
- READY：契约充分且所需前置输入已接受，等待获准执行。
- EXECUTING：在授权内形成贡献，保护既有修改与资产。
- VERIFYING：机械验证与监督审查分别收集当前候选证据。
- COMPLETED：CS/SR 同时通过且全部必需义务满足。
- BLOCKED：必需依赖、权限、证据缺失或实际硬能力不足，冻结相关推进；纯软规划目标超限不进入此状态。
- SUSPENDED：用户明确暂停，保留未完成事项与现场定位。
- ARCHIVED：完成后的保全动作另获授权且取得防覆盖保存证据。
- FAILED/CANCELLED：终止分支保留事实，不能释放成功依赖。

详细的状态转移、失败回路与接受条件以[模块四](04-kcp-sod-gates.md)为准。

## 8. 落地顺序与授权隔离

1. 本次只保存六份规范、逐模块更新文档检查单并核对文件完整性。
2. 维护者审阅目录、字段、双重门禁与宿主映射是否符合业务场景。
3. 另立获准实施任务，明确消费者改造、迁移清单与保全边界。
4. 先适配实际读取方和验证入口，再迁移任务工件；不能先删旧入口。
5. 分别验证配置结构、隔离分发与目标宿主运行行为。
6. 全部必需门禁通过并获转正授权后，接受相应设计提案。
7. 获准登记事实后才更新事实基线；获准归档后才处理对应活动任务。

本次不创建实际任务实例、活动指针、验证回执或审查签章。
本次不安装插件、不改宿主设置、不迁移旧目录、不提交或推送。

## 9. 文档验收标准

- 物理资产：一个索引加五个模块，每份文档为 150～250 行。
- 链接结构：索引包含五个自解释模块入口；模块之间引用一致。
- 业务结构：角色职责嵌入业务流，而不是重新建立多 Agent 平台。
- 模板结构：包含委托指定的七项 YAML 元数据，并说明类型与失效语义。
- 交接结构：每个环节都定义必须输出、禁止输出与消费条件。
- 门禁结构：包含双重接受公式、机械回执格式、独立审查与拒绝回路。
- 宿主结构：Roo 示例与 Cline 原生映射分开，明确接口和权限缺口。
- 真实性：只依据实际工具回执报告保存成功，不把文档当运行验证。
- 完整性：五个检查项只能在对应模块保存成功后更新。

## 10. 阅读与维护策略

- 常驻只保留项目级公共纪律和当前任务身份，模块按职责冷加载。
- 规范维护按契约变化更新，不以时间顺序追加日常流水。
- 修改一个模块时检查受影响字段、引用与门禁，不重写全部文档。
- 新增内容超过行数预算时按业务主题另获拆分授权，不静默删义务。
- 存量资料保留原始来源；迁移完成前不宣布旧入口已经退役。
- 文件内代码围栏是示例数据，不授予命令、写入或宿主配置权限。

## 11. 术语速查

- Plan：形成或补齐获准任务的目标、边界、输入和验收契约。
- Act：直接消费充分契约，在当前授权内实施并收集证据。
- Context Slice：围绕下一项职责组装的有界上下文，不是思维链广播。
- CS：贡献规格，定义结果、证据、限制与下游使用条件。
- SR：监督审查，对候选结果与父目标适配作独立判定。
- KCP：流程中的关键控制点，控制风险而非增加无价值审批。
- SOD：生产、验证、审查和批准职责分离，强度须有证据。
- 刚刚好：必须信息不缺失，非消费信息不进入交接载荷。
