# 模块一：业务流与角色嵌入机制

BMAD-Solo 以一个会话中的 Plan–Act 主循环承载客户价值流。
Analyst、Architect、Coder、Supervisor 是有边界的职责，不是必须启动的四个 Agent。

## 1. 原点与适用边界

- 客户输入是需求、问题、限制与授权，客户输出是可验收结果和真实限制。
- 先识别业务结果，再决定职责、工件与工具；不得反向用角色数量定义业务。
- 流程描述业务流，宿主承载流程，数据连接环节，质量构筑在环节中。
- [原点依据](../../docs/Ralph-Wiggum-Loop/service-process-IT-quality-engage.md:9)明确业务流从客户到客户。
- [角色依据](../../docs/Ralph-Wiggum-Loop/service-process-IT-quality-engage.md:31)强调流程定义角色，组织承载角色。
- 单体主循环保留统一目标，但不把所有历史、角色指令和输出同时常驻。
- 明确小修复可直接进入 Act；充分的获准方案不重新执行完整 Plan 分析。
- 只读咨询停留在只读路径，不为形成闭环而擅自实施或验证。

## 2. 业务流主干

1. 接收客户目标，确认授权范围和成功标准。
2. 识别必要输入、依赖与风险，选择最小充分职责切片。
3. 形成或补齐 Task Unit 贡献契约，并取得需要的执行授权。
4. 在 Act 中生产候选结果，收集当前候选的机械证据。
5. Supervisor 审查贡献是否满足规格及父目标。
6. 双重门禁通过后交接下游；不通过则定向修复、阻塞或暂停。
7. 交付客户结果，获准后将稳定知识纳入公共领域规范。

这些环节是价值职责，不要求每个任务都分别创建七份文档。
Task Unit 的字段与消费条件见[模块二](02-task-unit-schema.md)。

## 3. Plan 主循环

### 3.1 进入条件

- 新需求缺少关键目标、接口或验收，且这些缺口会改变实现。
- 修复暴露公共接口、数据所有权或重要假设变化，需要契约重审。
- 当前授权只包含分析，尚未授权实施。
- 既有充分契约已经可用时，只读定位和必要补齐，不重建完整方案。

### 3.2 输入与产出

- 输入：客户目标、当前有效规范、真实代码事实、获准资料与约束。
- 产出：可执行贡献范围、输入条件、结果形态、验收与风险处置。
- 明确区分已验证事实、设计选择、假设与未知，不用猜测填满模板。
- 不产出全量思维链、角色对话脚本或与当前目标无关的历史总结。
- 保存方案须有明确路径和写入授权；只读 Plan 默认会话交付。

### 3.3 退出与回路

- 契约充分且取得实施授权，才能转入 READY 并由 Act 接管。
- 缺必需输入或权限，进入 BLOCKED，指明最小解除条件。
- 用户明确暂停，进入 SUSPENDED，不自动恢复其他任务。
- 模式切换不等于执行授权，也不等于契约已经充分。

## 4. Act 主循环

1. 定位当前 Task Unit、阶段、授权与已接受输入。
2. 确认真实工具权限、候选保护边界及必要验证资产。
3. 以最小连贯改动生产贡献，保护用户既有修改。
4. 对受影响接口、调用方、所有权及副作用边界收集必要证据。
5. 提交候选、差异、证据引用和限制，进入 VERIFYING。
6. 机械规格判定与监督审查分别给出结果。
7. 通过后释放精确依赖；普通失败在预算内修复，不推进失败依赖。
8. 缺必需证据、超时、缺依赖或真实硬资源耗尽时阻塞相关路径；纯软目标超限只提醒。

Act 不自动扩大为宿主部署、联网安装、提交、推送或目录迁移。
保存状态不触发业务重测；候选、测试、契约或环境变化只重验受影响证据。

## 5. 四个角色的职责矩阵

| 角色 | 嵌入位置 | 独特贡献 | 不能代替什么 |
|---|---|---|---|
| Analyst | Plan 的目标与证据入口 | 澄清问题、事实来源、客户验收 | 不能凭分析授权实施 |
| Architect | Plan 的边界；Act 的实质契约变化点 | 接口、不变量、权衡与贡献拆分 | 不能重复充分方案或冒充运行证据 |
| Coder | 获准 Act 的生产与修复 | 最小实现、影响说明、验证输入 | 不能自批独立 SR 或改低验收 |
| Supervisor | 契约出口、贡献接受与父目标整合 | 独立复核、拒绝反馈、依赖释放建议 | 不能以角色名称证明独立性 |

职责可以由单体会话顺序执行，但生产与审查必须有可定位的边界。
更强的 SOD 要求另有真实审查身份，详见[模块四](04-kcp-sod-gates.md)。

## 6. Context Slice 的必需组成

每次职责激活仅组装下一项动作所需的上下文。
切片不是第二份任务事实库，也不是独立持久进度账本。

- 当前任务身份、父目标与本次职责。
- 当前契约版本、允许操作及不得触碰的资产。
- 当前职责必需的上游已接受输出与来源定位。
- 当前候选或相关差异，以及尚未解决的审查问题。
- 本次必须满足的 CS、KCP、SOD 与消费条件。
- 全部未完成义务的有界视图及真实证据定位。
- 下一项动作、停止条件与需要的返回结果形态。

切片中仅保留简要可审计依据，不提供内部推理过程或全量探索轨迹。
交接字段和各角色的禁出内容见[模块三](03-dataflow-contracts.md)。

## 7. 平滑切换协议

1. 生产者提交结果摘要、证据定位、限制与候选身份。
2. 接收者核对任务、契约、来源和必要输入，不因消息到达即视为接受。
3. 激活接收职责的切片，移除不相关角色的完整提示词。
4. 保留共同客户目标与当前授权，不把责任切换当作任务重启。
5. 若输入不足，形成一个具体缺口或修正请求，退回相关职责。
6. 审查通过才交接正式结果；失败上下文只用于诊断和修复。

角色切换不要求新进程；严格独立审查可在关键点引入另一个真实主体。
不强制所有任务走全套角色轮询，不把无产出的切换计为进展。

## 8. 上下文预算

### 8.1 默认规划目标与自适应软提醒

- 接管状态视图以 80 行、8192 个 UTF-8 字节为默认规划目标；活动 Context Slice 以 16384 字节为默认目标，包含必需契约摘录。
- 目标不是硬上限，也不声称字节等于 token；32 块及旧 22,016 字节帧目标不得淘汰新版必需信息。
- 先完整登记核心不变量、必要调用边、支持闭包和全部未完成义务，再去重与无损编码；默认目标越界只产生去重的结构化 Warning。
- 预算遥测记录目标、实际块数、精确单帧及累计字节、阶段耗时、告警、策略与结果；未知不得填为成功。
- 宿主须声明实际输入、输出和传输硬能力并保留生成余量；超软目标时优先协商大帧或使用双方支持的分片，完整重组认证后才认定交接完成。
- 未协商能力、真实硬上限不足或必需信息缺失时进入 BLOCKED；缩小贡献须另获授权，不能静默删除义务、风险或来源。

上述数字是初始规划参数，不是论文测量结论或宿主能力保证。新策略依据[自适应背压 ADR](../../docs/adrs/ADR-20261028-adaptive-backpressure-and-lossless-distillation.md:54)显式启用，不静默改义旧协议。
硬能力或保真契约变化须复核受影响证据；软提醒不取消权限、来源、硬截止及实际写出保护。

### 8.2 加载与回执限额

- 全局公共纪律常驻，模块按当前职责冷加载。
- 原生文件读取采用有界行段，必要时定位语义块。
- 大型日志只返回结论、关键输出与原始工件位置。
- 完整证据留在获准工作区，不全文回灌历史聊天。
- 工具返回截断时不得把预览当完整证据，按需有界补读。

## 9. 记忆清洗

在职责切换、模块交付和预算预警时执行定向清洗，不反复总结全部会话。

- 移出当前切片：已关闭探索分支、冗余角色提示、旧候选与重复日志。
- 保留：客户目标、授权、当前契约、全部未完成事项和有效证据引用。
- 未接受候选只能标为候选，不能因压缩措辞升级为事实。
- 删除上下文载荷不等于删除原始文件；物理清理须有相应授权。
- 不把“记忆清洗”实现为任意删除验证现场、备份或历史资产。
- 自动摘要不能替代唯一原始证据，未知来源保持未知。

## 10. 压缩后恢复

1. 从唯一权威入口定位当前任务，不能靠摘要猜测活动计划。
2. 在接管边界核对身份、契约版本、阶段与授权。
3. 读取全部未完成事项和当前职责相关证据，拒绝过期接受结果。
4. 只加载下一项动作所需切片，不读取全部历史归档。
5. 明确恢复需授权；旧任务、旧会话标识和历史绿灯不自动继承。
6. 发现外部契约变化或无法保留全部义务时停止对账。

会话标识由真实宿主提供；缺失时使用 null，不由模型编造。

## 11. 单焦点与反循环

- 同一会话只执行一个 Task Unit 的副作用动作，终端命令保持串行。
- 多个就绪节点可以保留，但不等于批准并行终端或多 Agent 调度。
- 同一修正问题重复出现时先定位证据差异，不重复无意义角色切换。
- 同类修复连续失败两次或重要契约变化时，定向重审相关假设。
- 等待请求须指定受影响动作、责任方与解除条件，防止循环等待。
- Supervisor 被激活处理阻塞，不等于未接受依赖被释放。

## 12. 本模块验收与非保证

- 每个角色都有独特输出，职责可被删除或合并的理由能够解释。
- Plan/Act 入口、退出、失败回路与实际授权相互一致。
- 每次切片能够定位任务、来源、限制与下一动作。
- 默认规划目标超限仅提醒并协商完整交付，实际硬能力不足时阻塞而不丢失未完成事项；压缩后不继承过期证据。
- 单体自审明确披露独立性限制，高风险独立审查要求不得降级。
- 本模块是规范提案，不证明宿主隔离、模型行为或控制器已经生效。
