## 唯一版本：V4

唯一来源为 [V4 套件](bmad-suite-v4/)。安装和分发无需选择主版本；兼容已有 V4 参数，其他版本拒绝。已有部署必须通过所有权、摘要和 V4 身份核验，未知、退役或被修改的资产阻塞，显式 V4 参数也不能绕过保护。

V5 已按维护者确认独立迁至 solo-engine，本仓库退役其源码与专属测试，不提供 V5 激活或自动迁移。[V5 冻结计划](_bmad-output/archive/plans/plan-20261021-BMAD-ANTI-BUREAUCRACY-20261012-01-frozen.md)及历史 ADR、回执保留，不代表 V5 开发完成；历史源码路径仅供追溯。

## 🚀 快速开始与部署

本项目采用受管资产物理分发：通过[部署入口](bs.sh)将插件、共享规则和选中的 Roo 模式配置交由统一协调器处理，不删除共享目录内未知资产。已有受管文件发生修改或缺失、配置损坏、链接边界不满足要求时，停止处理并报告冲突。

文件分发成功不等于 Roo 已加载规则、权限配置已生效或模型行为已经通过验证。隔离回归覆盖 Linux 存储布局，包括含空格的本机 Antigravity IDE 路径；目标 Roo 版本、实际扩展宿主及权限交互仍须单独验收，不承诺所有 IDE 或操作系统兼容。

### 安装前提与授权

先获取并审查可信版本的仓库及[安装入口](install.sh)，不建议将远程脚本直接通过管道执行。默认部署会写入当前用户的全局配置；执行前应确认目标和授权。已有安装仓库存在未提交改动或缺少本地主分支时，安装入口拒绝继续，不自动丢弃改动。

安装入口仅分发 V4，兼容已有 V4 调用；退役版本参数在克隆或更新之前拒绝，V4 来源缺失不回退其他目录。安装、更新、文件分发及 IDE 重载不启动任务、不准备模型认证、不提交、推送或部署业务服务。

当前实现需要 Bash、Git、GNU timeout、Python 3.10 或更高版本及 PyYAML；2026-10-13 本机复核环境为 Python 3.10.12 和 PyYAML 5.4.1，不将历史检查环境当作当前状态。运行环境和权限仍需按实际宿主核验。

### 本地部署与版本操作

以下命令在已审查的仓库根目录执行；真实部署、更新及卸载必须获得目标目录写入授权。先运行模拟预检，再决定是否执行写入。

```bash
# 列出当前套件的迁移范围、逐项接管阻塞及保留的旧资产；不授予写入权限
 timeout 30s bash bs.sh --preflight < /dev/null

# 当前套件的只读部署预检
 timeout 30s bash bs.sh --dry-run < /dev/null

# 获准写入后分发唯一 V4；不启动任务，不证明宿主已加载
 timeout 30s bash bs.sh < /dev/null

# 只读检查受管摘要、事务状态及记录的来源
 timeout 15s bash bs.sh --status < /dev/null

# 仅预览更新动作，不访问远端或切换分支
 timeout 30s bash bs.sh --dry-run --update < /dev/null

# 查看已有标签
 timeout 15s bash bs.sh --tags < /dev/null

# 仅预览指定标签；标签必须在本地存在
 timeout 30s bash bs.sh --dry-run --tag v4.2.0 < /dev/null

# 预览卸载；实际卸载仍会保留未知资产
 timeout 30s bash bs.sh --dry-run --uninstall < /dev/null
```

真实版本操作及卸载参数见[部署入口](bs.sh)。更新需要干净工作树并仅允许快进；已有部署身份在网络访问和分支切换前核验。成功核验提交后执行磁盘新版入口，不继续旧版部署尾部；续接保留部署根目录及显式模式目标，再次核验 main、提交和工作树，禁止重复更新。

标签部署绑定实际提交及 V4 身份，保持 V4 提交缓存格式；标签名仅是版本线索。缺源、身份矛盾、非 V4 标签线索或缓存被修改均拒绝，不回退、不自动修复缓存。主分支切换同样移交新版入口。

旧版本不作为降级目标。未包含移交整改的历史入口不会自动获得新保护；首次应用先结束旧进程，再从审查后的入口启动。

### 目标发现与显式覆盖

默认只读探测 Antigravity IDE Server、Antigravity Server、VS Code Server / Insiders，以及本机 Code、Antigravity IDE 和 Antigravity 的 Roo 存储。还会在部署根目录的本机配置目录下发现已有的单层 IDE 配置布局；不扫描整个用户目录、不创建缺失候选，也不从 Gemini 插件镜像推断有效 IDE 模式。

本机含空格的 [Antigravity IDE 模式配置](.config/Antigravity%20IDE/User/globalStorage/rooveterinaryinc.roo-cline/settings/custom_modes.yaml) 相对于部署根目录，不是项目内的配置。候选目录存在不证明它属于当前活动扩展宿主；合法空模式列表可新增来源模式，空文件或损坏 YAML 仍失败关闭。没有模式目标时仅处理文件资产，不称完整激活。

可通过部署根目录环境变量和可重复的模式目标参数覆盖自动探测。下面仅对预先创建的项目内沙箱执行只读预检，不创建目标目录：

```bash
BMAD_DEPLOY_ROOT="$PWD/sandbox/deployment" timeout 30s bash bs.sh --dry-run --mode-target 'ide/settings/custom_modes.yaml' < /dev/null
```

显式模式路径相对于部署根目录；提供显式目标后跳过自动候选探测。重复路径、越界路径、链接及损坏配置由受管入口检查，不能用覆盖参数绕过资产保护。

### 冲突、备份与恢复

- [只读迁移预检](scripts/deployment_preflight.py:39)列出全部来源文件、模式目标、历史受管退役项、同路径文件及逐目标同标识模式阻塞，并盘点相关容器内保留的未知旧资产。没有所有权记录是迁移授权阻塞，不代表文件损坏；即使旧文件与来源完全相同，也不能自动视为受管。
- 范围预检不能与真实更新、版本切换、卸载或接管授权组合；它只检查当前已物化来源，不创建状态目录、锁、事务、缓存或 Python 字节码。存在阻塞时非零退出；普通部署和模拟部署也会在任何资产写入前报告迁移阻塞。
- 首次同路径文件或同标识模式冲突不会自动接管。应审查逐项内容差异、权限及目标宿主，再次明确授权后才通过[受管命令入口](scripts/deploy-managed-cli.py)提供逐文件授权或逐目标模式授权；不能将预检输出直接自动转换为批量授权。个人模式与第三方顶层字段保留，不自动清理来源外的旧文件或目录。
- 写入采用原字节备份、单文件原子替换、单写者锁和提交前复核；所有权及事务记录位于部署根目录内的状态目录。多目标处理不是跨目录整体原子提交。
- 普通提交异常尝试恢复本批次资产，并保留事务证据。遇到未完成事务、恢复受阻或强制终止，应停止重试写入，先审查日志、备份及当前文件；不要删除状态目录来绕过保护。
- 状态诊断核对磁盘受管资产，并报告经过摘要检查的套件身份、主版本、仓库内源路径、实际源目录、提交及差异；不访问来源仓库确认实时同步。来源差异标记仅针对分发套件，不表示整个仓库洁净。旧记录无法唯一识别时报告未知，不按当前 HEAD 或默认版本猜测。
- 单一部署根只分发 V4，不支持旧版本回切或双活；旧部署身份阻塞，不自动迁移。真实宿主处置须单独授权，个人模式、第三方资产及恢复证据继续保护。
- 同账号能够修改文件与清单；一致性检查不等于程序防篡改或权限隔离。活动任务期间不得替换绑定套件，先停止并确认在途进程结束；任务期写入锁与部署联动仍属于控制器阶段待验能力，不以规则文本宣称已实现。

### Roo 重新加载与运行时验收

确认实际 IDE、扩展宿主及 Roo 版本，检查项目级同名模式是否影响有效配置，再执行 IDE 的 Developer: Reload Window。不要仅凭全局文件存在推断其生效，也不要自动删除项目配置。

随后在获授权的隔离环境验证分析模式终端拒绝、生产文件写入拒绝、允许的文档编辑，以及工程模式验证能力。保存版本、有效模式、用户输入、工具请求及实际结果；静态配置校验和磁盘分发测试不能代替这些交互证据。

## 🛠️ 核心指令与人机交互极简指南 (V4.2)

彻底告别繁重的内部 Procedure 名词记忆，人类仅需使用 3 句直觉白话：

### 1. 发散与查漏补缺（拉家常式讨论，0 污染）
* **`/ana-solo [业务问题/架构设想]`**：
  触发独立深度分析通道。日常咨询、排查、探查走 **Ephemeral 模式**，零持久文件落盘，绝不污染工程；遇到重大技术选型时自动加载 Keshav 三读法与决策矩阵推演。

### 2. 成熟收敛，一键结晶（建立前置背压屏障）
* **`/ana-solo 方案ok`**（或输入 `结晶`、`可以了`）：
  获得明确授权后结晶；先检查已有活动任务，不覆盖无关计划：
  1. 产出一流公民架构决策记录：`_bmad-output/adrs/ADR-*.md` (`Status: PROPOSED`)；
  2. 提取纯净待办暂存区：`_bmad-output/pending_implementation_plan.md`，并自动打上场景指纹（`scenario: algo | structural | bugfix | ops`）与测试命令。

### 3. 一键执行，场景自适应与背压护航
* **`/bmad-solo 执行`**（或输入 `开始`、`按计划做`）：
  执行入口先判断意图和授权，再按三级路由选择契约：用户显式指定优先；没有显式路径时探测相关活动计划；默认入口缺失时只读发现归档候选或进入空闲、选择及轻量任务路径。显式文件缺失不得静默替换，历史计划恢复须重新授权和验证，只读任务不进入实施。绑定实际计划后按场景选择验证：
  * **算法场景 (`algo`)**：按[算法契约流程](bmad-suite-v4/skills/bmad/references/procedures/algorithm-fit.md:9)和[架构预检](bmad-suite-v4/skills/bmad/references/procedures/architecture-preflight.md:9)核对适用约束，以相关真实验证阻断失败；必要实验不自动启动。
  * **结构场景 (`structural`)**：使用[架构预检](bmad-suite-v4/skills/bmad/references/procedures/architecture-preflight.md:9)，按契约选择配置校验、隔离分发或相关单测，不附加算法检查或无关业务测试。
  * **缺陷场景 (`bugfix`)**：跳过重型架构门禁，执行覆盖受影响接口、调用方及副作用的最小充分相关回归；属性测试与缺陷回归互补，不按比例删测，不建立或转正 ADR。
  * **运维场景 (`ops`)**：审查相关差异与配置语法，不盲跑业务单测；差异检查通过不等于工作树无改动。
  * **完工对账**：阶段通过不等于全计划完成。仅绑定契约要求关联 ADR、全部必需门禁通过且取得转正授权时接受对应提案；仅取得相应写入授权时在[项目事实基线](_bmad-output/project-context.md)登记已验证事实及溯源，阶段交付不自动更新事实基线。仅全计划完成且获准归档时处理实际绑定的活动计划，目标包含时间和计划标识且禁止覆盖；确认完整保存后复核源标识与内容版本，失败或源已变化则保留源，不清理无关任务。必需运行时证据缺失时保持阻塞及提案状态，不以静态测试或自治裁决替代验收。
