## 2. 当前源码与历史归因的差异

### 2.1 不把未证实的度数算法当根因

[当前场景 A](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:501)先预留请求中必需静态选择器的所属定义，再进行一次模型导航；本地没有全局度数排序。[场景 B 定位](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:81)使用种子或问题词匹配，也不是入度排名。

[调用记录](../../../project/solo-distill-mcp/src/solo_distill/extractor.py:211)保留调用表达式且目标解析为未知。调用表达式数不能直接替代已消歧调用边数，文件导入数也不能直接证明生命周期图完整。

当前 A 在一次正文读取前将候选并集限制为 32，且创建新读取器；这与历史“读满后另有七项 candidate_block_budget”描述需要版本对账。不得据此否定历史现场，也不得未经绑定便将原因确定为当前实现中的度数贪心。

### 2.2 已定位的结构性缺口

1. [候选域](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:55)只有定义；模块顶层装配、入口保护块与副作用不能直接成为正文候选。
2. [必需预留](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:106)只保护请求中明确的直接静态证据；语义维度没有本地生命周期覆盖契约。
3. [正文读取](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:160)已有完整定义、身份与字节检查，但没有角色隔离或固定骨架的 1-Hop 扩展。
4. [现有压缩](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:168)已经保留共享来源列表；不是每个结论都内嵌完整路径。重复成本需对文件身份、关系记录、维度、诊断和二次转义分项测量。
5. [小预算回填](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:217)先装结论，再尝试关系与未完成事项；仅有遗漏计数与追踪指针不足以称为完整自包含知识包。
6. [语义维度满足检查](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:613)验证有效引用并保留独立语义审查要求；不能升级为“引用存在即结论正确”。
7. [服务耗时记录](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:550)早于追踪保存和最终压缩，不能单靠该值证明整个交付都处于截止内。

先筛授权、证据守恒、32 块／96 KiB／24 KiB／180 秒，再比较改动面、可逆性及后续验证成本。缺少性能及权重数据，不生成伪精确加权分数。

## 5. 推荐算法契约

### 5.1 DAG：可信关系与生命周期角色

- 分层维护导入、调用、构造、注册关系；词法作用域、别名、重绑定与条件参与消歧。仅保守可证明的目标进入确定邻接表，反射、动态分派、复杂别名和未知继承保留未知。
- 使用迭代 SCC 凝聚与稳定拓扑，目标时间复杂度 O(V+E)；不执行全节点对介数或无界社区优化。图分量只作静态区域，不强装成唯一生命周期。
- 角色为入口触发、装配初始化、状态编排、持久化边界；补充异常／资源边界和辅助类别。允许多标签但一次入选只消耗一块。
- 入口来自完整主程序保护块、获准声明式入口或可识别注册；构造器名称仅为候选信号。编排须结合组件调用、状态和值传递，不将任意字典赋值判为核心。
- 文件名、框架关键词及高入度不能授予骨架资格；非 Python 配置只有在授权集合覆盖时才能读取。不得导入目标模块执行分析。
- 不同调用方、不同被调用方分别去重；重复调用不加邻居数。饱和函数 h(d)=d/(d+8)，中心度只在同角色、同信号等级内破同分，参数随算法版本固定，非已调优事实。
- 排序为：完整满足未完成必需证据组 → 新角色／区域 → 结构信号档位 → 新增已定位跨组件关系 → 饱和度 → 正文成本 → 稳定路径与位置。角色轮转在该排序之外，辅助节点不得跨角色掠夺配额。

### 5.2 RAG：配额、证据组与合法单元

首版评审候选采用三个固定管道：骨架最多 16 块、上下文最多 12 块、异常／资源边界最多 4 块，总计最多 32。不是每角色机械四块，也不是无条件覆盖保证。

调度顺序：

1. 构建合法语法单元、保守绑定与角色队列，定位请求契约的必需证据组；不读取独立验收答案。
2. 每项义务表示为若干可替代证据组，组内调用方、被调用方或条件须整体试装，不能半组选入后登记完整。
3. 优先预留必需组，再按未覆盖角色和组件轮转，完整加入候选；去重后计块与真实 UTF-8 成本。
4. 固定骨架集合，从确定邻接关系展开一次 1-Hop。新增上下文不成为下一轮种子，每文件可选上下文最多两块；同文件必需证据不受该可选上限限制。
5. 补与骨架有关的异常／资源边界，校核所有义务和预算；没有合法证据仍保持未知或未选读。

合法正文包含完整函数／方法及装饰器、完整模块顶层语句、必要完整类；条件和清理上下文不得被摘掉。单独类头只能标为结构片段，不充当完整类证明，不得用整个模块包装成“一块”绕过限制。

父子重叠以已读完整父定义支持真实子范围引用；新增别名不增加正文块，但必须保留真实正文索引和 AST 校核。先选方法后选父类须计算替换后的整体成本及义务，不重复累加。语法位置结合 AST、Token、列位置和编码映射，同行语句不能粗暴按行混切。

骨架必需组超过 16，即使总数可能小于 32，固定管道仍可能阻塞。这是公开的策略代价：本轮推荐先保持上述固定候选与失败关闭，不静默借槽；若用户希望采用“16 块保护底线、必需组可借未用上下文槽”，须明确批准新配额策略及回归要求后才能替换。

### 5.3 覆盖义务分类

扫描覆盖、正文选读覆盖、结论支持分开。义务的必需／可选属性只来自请求与获准契约，模型不能更改。

- 直接静态满足：匹配本地语法且来源身份、范围成立；不证明运行时执行。
- 有来源推断：来源有效但语义仍需独立审查；不能自动顶替直接要求。
- 未知：语言、绑定或语义规则不够；保留原因。
- 未选读／预算阻塞：缺正文、证据组超限或必要来源不足；不得改为不适用。
- 不适用：须由明确输入范围或可核对事实支持，而非“没有找到”。

非 Python 资产是否仅承担清单义务，由场景契约决定；请求必需内容不支持时仍阻塞对应维度。解析失败、秘密边界、软链接拒绝及来源变化不能用“全库概览”名义消除。

## 6. CAG 与 Wire：发布格式和预算闭环

### 6.1 共享引用的最小数据模型

| 对象 | 内容与约束 |
| --- | --- |
| 候选 | 稳定内部标识、文件身份、语法范围、限定名、单元类型、角色集合、信号档位、组件、正文成本 |
| 关系 | 类型、方向、调用点、条件、目标消歧状态；未知目标不得制造边 |
| 义务 | 标识、必需属性、证据等级、替代证据组、满足／未知／未读／阻塞状态 |
| 文件表 | 每个相对路径和文件摘要只存一次；不跨项目或快照合并 |
| 来源表 | 文件索引、符号、范围、正文索引、必要条件；来源整数索引仅作本包引用 |
| 事实与关系表 | 引用来源及条件索引；保持证据等级与适用边界 |
| 知识核心 | 项目／快照、算法／schema／策略版本、规范化范围、事实、来源、全部必需义务 |
| 单次观测 | 请求 ID、耗时、追踪和传输观察，与稳定提示前缀分离 |

共享身份减少重复，不截短文件内容摘要值、不降低摘要算法强度或丢失必要定位；可选说明可以压缩，但不能改变必要事实。字典化收益必须以实际帧测量；短小且不重复的数据可能因表开销增大。

### 6.2 序列化与安全裕度

- 不变硬门禁：正文最多 98,304 字节，最多 32 块；A 完整 JSON-RPC 帧最多 24,576 字节，B 最多 12,288 字节；两者还受调用者更小预算约束。
- 待评审发布目标：A 完整帧默认打包上限 22,016 字节，包含内层 JSON、二次转义、工具封装、请求身份与结尾换行；相较硬门禁保留 2.5 KiB。不是测内层正文得到“22 KiB 即安全”。
- 首先装入身份、状态、全部必需义务、必要事实及其完整引用闭包、必要未知，再按固定顺序填可选说明和诊断。
- 每个试装候选用实际规范化 JSON 编码测完整帧；非 ASCII、引号、反斜杠、控制字符均按标准 JSON 编码，禁止字节硬切或重复转义。
- 最小必需包超过发布目标时默认阻塞；如要在 22,016 至 24,576 间降裕度交付，须评审批准降级政策，不能隐式回退。本政策更严于原硬门禁，是候选决策，不自动成为已生效配置。
- 连硬门禁内的最小必需包也放不下，发送已测量的类型化错误，明确知识包未交付；不以追踪指针、遗漏计数和 complete 状态替代完整包。
- 最终检查与发送使用同一字节串；不检查对象后另行构造更大的帧。保留[现有精确封装原则](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:91)，不退化为只测摘要。

### 6.3 稳定前缀不等于供应商缓存

稳定知识核心不包含时间戳、随机请求标识或逐轮诊断；来源顺序规范化，消费者把知识核心渲染为固定前缀，问题追加在后。

缓存键覆盖项目、授权范围、源快照、解析／算法／策略及影响结果的契约版本。变化后重新验证受影响输入；不借缓存跨越权限边界，也不承诺可变工作树无需任何新鲜度检查。

首个修复阶段只实现缓存友好的数据布局，不自动建设持久缓存、后台刷新、Redis 或供应商缓存管理。KV-Cache 命中、保留窗口、计费与零检索收益仍待有效供应商契约和消费者回执；未知局部继续按需检索，不能称全景无盲区。

## 7. 截止与版本化实施影响

## 8. 验收与 13/13 的证明边界

### 8.1 可证明不变量

经真实实施与属性／回归验证后，可以证明：块数与正文字节不超限、辅助节点不侵占骨架、重复邻居不增度数、来源去重不造正文、引用闭包完整、必需义务不被压缩删除、证据不被提升，以及实际发送帧在预算内。

不能仅凭上述不变量证明任意代码库全部架构锚点都被选择。四类角色不等于 13 项事实，低度数保护也不等于所有低度数节点必选。

### 8.2 13/13 条件性推演

每个独立锚点须存在合法证据组，并且通用选择规则实际选中它；骨架并集不超过 16、扩展不超过 12、边界不超过 4；累计正文不超过 96 KiB；必要事实与来源完整帧不超过批准发布预算；源版本和截止成立，独立驱动能校验新来源结构。

若 13 个锚点每项只需一个不同骨架单元，则 13≤16 留出三个槽；这是容量条件，不是本库证据映射或分类器选择证明。固定预算下，大量同角色同信号节点中总会有落选可能，不能给出任意隐藏测试的普遍 13/13 定理。

正文覆盖、语义支持、传输结构、真实宿主和清理分别验收；[现有锚点检查](../../../project/solo-distill-mcp/tests/run_live_integration.py:99)也保留独立语义审查要求。不得改冻结答案、生成后选容易锚点、按命中反馈加项目特例或降低断言。

### 8.3 最小充分回归与后续顺序

| 验证组 | 必需覆盖 |
