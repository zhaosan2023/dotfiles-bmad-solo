# 动态背压松绑与无损蒸馏：正式分析草案

采用“保真硬门禁、预算软背压、传输能力协商”的三层架构，取消任意块数和字节规划目标对必需信息的裁减或阻断。保留来源认证、权限、真实资源边界、取消、截止时间和交付完整性检查；本草案不是实现或验证通过声明。

## 1. 目标、授权与证据边界

- 用户目标：在业务不变量和必要证据完整的前提下，消除表示冗余，压缩至最小充分表示，而非通过删除骨架来省 Token。
- 规范契约对象：dotfiles-bmad-solo，负责治理规范、验收定义和架构决策。
- 代码实现对象：solo-distill-mcp，负责候选选择、证据读取、上下文管理、编码、协议交付及遥测。
- 草案阶段授权：创建本分析、[架构提案](../adrs/ADR-20261028-adaptive-backpressure-and-lossless-distillation.md)和[任务契约](../../specs/tasks/archive/20261028-adaptive-backpressure/TU-20261028-ADAPTIVE-BACKPRESSURE.md)，给出第二工作区执行交接。以下保留草案阶段的事实与授权，不因导航迁移改写为后续运行证据。
- 证据来源：本会话原生读取回执及下列源码定位；第二阶段接管时复核当前版本和既有改动，不继承历史绿灯。
- 本次不恢复或覆盖其他活动计划，不建立第二份任务进度账本。控制器覆盖未证明，进度临时使用平台任务记录。

## 2. 五处多层叠加病灶

### 2.1 正文读取层：32 块与 98,304 字节

[配额定义](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:19)将正文限制为 32 块和 98,304 UTF-8 字节。

- [必需候选检查](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:130)在必需候选超过 32 块时抛错，导航校验也混入同一容量条件。
- [正文读取路径](../../../project/solo-distill-mcp/src/solo_distill/evidence.py:185)在超出块数或累计字节时跳过完整候选并登记未完成项，不是直接截断函数正文。
- [V2 读取路径](../../../project/solo-distill-mcp/src/solo_distill/evidence_v2.py:99)另行拒绝超过 32 个正文所有者或 98,304 字节的完整包。
- 病灶：任意配额改变必需证据可获得性；即使不伪报成功，也会在大型项目中制造可避免的阻塞。

整改：必需来源与完整正文先按业务契约保留；块数、累计正文量改为软目标，驱动计量、分批和资源准备。类型、身份、秘密筛查、来源变化及真实截止检查不能删除。

### 2.2 导航层：240,000 字节与候选前置裁减

[导航入口](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:504)在骨架 JSON 超过 240,000 字节时阻塞；必需候选与导航候选合并超过 32 块时再次阻塞。

[V2 候选入口](../../../project/solo-distill-mcp/src/solo_distill/live_v2.py:81)还存在按排序仅取前 48 个叶单元的前置选择。完整文件分母不等于所有骨架节点均已进入后续候选域。

整改：先建立授权范围内的完整骨架注册表，再按稳定身份分页导航；不得将前 N 个单元冒充全项目骨架。240,000 是现有字节常量，不能混称为模型 Token 容量或已测宿主硬能力。

### 2.3 V2 调度层：16/12/4 与借槽政策

[调度判定](../../../project/solo-distill-mcp/src/solo_distill/scheduler_v2.py:130)采用骨架 16、上下文 12、异常 4 的政策，并设置单向借槽；必需组合可能在总量仍可容纳时因管道比例被拒绝。

[可选填充](../../../project/solo-distill-mcp/src/solo_distill/scheduler_v2.py:204)继续按总块数、正文成本、各管道限额及每文件规则排除候选。

整改：完整必需闭包不再受管道比例和借槽拒绝；分类保留为优先级与探索规划信号。保留归并、别名真实性、确定排序、循环处理及搜索资源边界，不能以无限组合搜索代替固定配额。

### 2.4 V2 发布层：22,016 字节完整帧

[核心封存入口](../../../project/solo-distill-mcp/src/solo_distill/core_v2.py:333)因最小必需核心超限而阻塞；[发布入口](../../../project/solo-distill-mcp/src/solo_distill/wire_v2.py:122)在去掉观测仍无法满足预算时返回知识未交付的阻塞帧。

- A 场景的 22,016 字节计入 JSON-RPC 身份、嵌套转义和换行，不是正文配额。
- [旧交付压缩](../../../project/solo-distill-mcp/src/solo_distill/distillation.py:141)另有缩短文本和仅指针子集逻辑；原件保存不证明下游已消费全部必需信息。
- [现有客户端](../../../project/solo-distill-mcp/src/solo_distill/client.py:108)仍拒绝超过 24,576 字节的帧，[V2 消费者](../../../project/solo-distill-mcp/src/solo_distill/consumer_v2.py:105)仍检查场景上限。

整改：新策略将旧数字降为软规划目标；消费者支持的大帧能力或分片协议必须显式协商。旧版本保持兼容，不能单独删除生产者限制并向旧客户端写超大帧。

### 2.5 棕地文档入口：结构交付与文档渲染耦合

[棕地入口](../../../project/solo-distill-mcp/src/solo_distill/brownfield.py:86)先将扫描原件经过受限交付，再从交付表示展开审查文档；核心阻塞时拒绝文档生成。

[结构交付包装](../../../project/solo-distill-mcp/src/solo_distill/extractor.py:472)实际委托[优先交付逻辑](../../../project/solo-distill-mcp/src/solo_distill/priority_v1.py:125)，并非走正文蒸馏的同一条路径。

整改：文档渲染消费完整、当前、获准的结构原件，传输表示单独规划。超出单页目标时完整分卷；保存总量、页面导航、来源及缺口。当前文档和整包资源保护仍须区分规划目标与真实存储约束，不能机械删除所有限额。

## 3. 一手论文机制映射及外推限制

### 3.1 Figure 9：近预算提醒与工具错误指导

[Figure 9 原文](../paper-analysis/google-ooharness.md:789)描述继承缺写入完成检查，接近轮次上限且尚无成功写入时提醒，再增加不可恢复错误或重复无产出结果的指导。

- 项目映射：接近预算时提示当前覆盖、未完成义务和可行下一步；纯软预算超限产生结构化 Warning，不物理抛容量异常。
- 错误指导必须分类：软目标超限建议去重、无损编码或分页；权限拒绝、断管、损坏证据及不可恢复资源错误仍报告真实失败。
- 外推限制：论文案例针对轮次和写入进展，不直接证明应取消所有传输安全或资源上限。

### 3.2 Appendix B.3：进展驱动压缩绕过

[Appendix B.3 原文](../paper-analysis/google-ooharness.md:851)的精确触发是提前完成尝试之后，后续工具输出绕过原有长响应压缩。

- 项目化扩展：新出现的必需来源、条件、调用关系、失败证据或未完成义务加入保护集；相关内容绕过有损摘要与裁减。
- 进展由本地可核验状态变化认定，不凭模型宣称“有进展”放开全部上下文。
- 区分有损语义压缩和无损传输编码：保护关键证据不意味着禁止无损压缩、去重或分片。
- 外推限制：通用关键进展绕过属于待验证项目设计，不能冒称论文证明了任意业务语义绝对无损。

### 3.3 Listing 1：继承能力与策略分层

[Listing 1](../paper-analysis/google-ooharness.md:610)展示[父类上下文方法](../paper-analysis/google-ooharness.md:614)复用父实现后执行字面量保护，子类继承该行为并叠加完成检查。

拟分离三种职责：

1. 业务保护策略：声明必需信息、支持闭包和禁止裁减项。
2. 上下文管理策略：对非必需材料做确定性去重、摘要与选择，识别进展保护事件。
3. 传输底层：负责规范编码、协商、分片、写出与回执，不自行裁决业务事实。

继承与方法重载用于复用保护能力，不授予子类绕过底层身份、协议和资源检查的权限。策略输出还需独立保真核验，不能仅凭调用父实现认定安全。

### 3.4 运行态摘要与对照改进

[Section 5.1.1](../paper-analysis/google-ooharness.md:281)、[Table 4](../paper-analysis/google-ooharness.md:827)和[路由摘要字段](../paper-analysis/google-ooharness.md:560)支持依据可观察执行记录选择干预或复用干净结果。

## 4. Before vs After 状态机

| 事件 | Before | After：拟议状态与动作 |
|---|---|---|
| 必需块数超过 32 | 拒绝或跳过候选 | 保留完整闭包；软告警；分批读取 |
| 必需正文超过 98,304 字节 | 跳过完整定义或阻塞包 | 完整单元保留；调整批次和受控存储 |
| 骨架超过 240,000 字节 | 阻塞导航 | 完整登记；稳定分页；汇总覆盖 |
| 管道比例冲突 | 政策拒绝 | 取消必需配额拒绝；保留分类与优先级 |
| 接近软目标 | 主要事后处理 | 近预算提醒；给出保真表示建议 |
| 新关键证据出现 | 静态压缩不区分进展 | 更新保护集；绕过有损压缩 |
| 必需核心超过旧帧目标 | 返回未交付知识的阻塞帧 | 新能力下大帧或分片；未协商则等待能力补齐 |
| 来源变化、缺必需证据 | BLOCKED 或部分结果 | 保留故障和原件；相关接受仍不放行 |
| 取消、硬时限、断管 | 失败且不接受 | 保持真实失败，不降为普通 Warning |
| 完整写出 | 写出不证明宿主消费 | 写出、重组核验和业务接受分开记证据 |

表示策略子状态：完整取证 → 保护闭包 → 去重与无损表示 → 预算评估 → 直接交付／大帧协商／分片 → 重组认证。

此子状态不替代任务生命周期。软目标超限不进入 BLOCKED；缺授权、硬能力不支持、真实资源故障或必需证据不足才阻塞相关动作。明确暂停为 SUSPENDED，机械成功不自动产生独立 SR 批准。

## 5. 覆盖义务分类

| 类别 | 内容 | 可否缩减 | 核验方式 |
|---|---|---|---|
| 业务必需义务 | 不变量、否定、条件、所有权、副作用及验收边界 | 不可删减 | 预先固定非空必需集合，独立逐项审查 |
| 骨架与直接静态边 | 授权范围内支持的语法单元、文件分母、已消歧关系 | 不因软配额删减 | 独立预期集合、身份与闭包比对 |
| 必需支持证据 | 来源、完整正文、条件来源、关系支持 | 不可截断或改为不可消费指针 | 原始字节及坐标认证、引用闭包检查 |
| 未知与失败义务 | 动态调用未知目标、解析失败、不支持资产、拒绝项 | 不可隐藏或计为通过 | 保留原因、范围、解除条件及来源 |
| 可选探索材料 | 与本次验收无关的补充片段、重复日志 | 可去重或按策略不加载 | 明确可选身份，不影响必需闭包 |
| 遥测义务 | 目标、实际用量、告警、策略、真实结果 | 可聚合，不得伪造或漏必需记录 | 原始事件与摘要对账 |
| 安全与能力义务 | 权限、来源、输入、解压、截止、分片完整性 | 不松绑为软提醒 | 保留正负控及真实回执 |

覆盖率 100% 的分母必须在验收前冻结，绑定项目、快照、范围和契约版本；未知、缺证据和未经审查项不计为已满足。完整骨架覆盖、已知调用边覆盖和业务语义成立是不同结论，不能以一个数字互相替代。

## 6. 两层整改与运行遥测

### 6.1 规范契约层

草案提出修订[数据交接](../../specs/governance/03-dataflow-contracts.md:183)、[接受门禁](../../specs/governance/04-kcp-sod-gates.md:126)、[预算定义](../../specs/governance/01-plan-act-role-embedding.md:118)和[宿主适配](../../specs/governance/05-host-adaptation.md:150)，同步确有冲突的分发源。本分析保留设计意图，后续规范收口由任务契约及当前授权独立约束。

验收从“帧不超过旧字节值”改为“必需覆盖 100%、表示无损、预算记录完整、协商交付可完整消费”，安全检查和独立审查保留。

### 6.2 引擎层

优先改造[证据读取](../../../project/solo-distill-mcp/src/solo_distill/evidence.py)、[蒸馏入口](../../../project/solo-distill-mcp/src/solo_distill/distillation.py)，拟新增[遥测模块](../../../project/solo-distill-mcp/src/solo_distill/telemetry.py)。新模块是拟建资产，不是已存在实现。

还必须覆盖上述 V2 读取、调度、候选、核心、传输、消费者和棕地路径；只改三个入口不能宣称全链路解除旧门禁。

拟议 BudgetTelemetry 记录运行身份、各阶段耗时、唯一正文块数、正文字节、原始核心字节、编码字节、精确单帧与累计字节、软目标、协商硬能力、告警、压缩绕过原因及交付结果。

- 后台记录指逻辑观测通道，不自动新增后台线程、进程或网络任务。
- 标准输出只承载协议；短提醒去重，避免标准错误洪泛触发客户端诊断限额。
- 计量包含自身摘要、真实请求身份、所有转义和换行。待发帧冻结后不为补写遥测重编码核心。
- 写出耗时及结果只能在取得真实回执后记录。未知模型容量、内部调用次数和成本保持未知。
- 必需遥测无法完整保存或回执缺失时，遥测验收不能通过；但不得因此删除已有业务证据。

## 7. 大帧与分片协商

- 使用显式新策略／协议版本；旧 V1、V2 和场景 B 不静默改义。
- 单帧能力需由双方确认；调用者硬上限、模型输入能力和真实资源上限不自动降为软目标。
- 能力支持时完整帧可超过 22,016 字节并记录 Warning；不支持时通过已声明的分片调用或通知机制交付。
- 每片绑定包、项目、快照、契约、编码、序号及完整性摘要；清单保留总片数、总字节和总摘要。
- 不为同一请求发送多个未声明的最终响应。接收端只有完成重组、身份和闭包认证后才登记知识交付完整。
- 缺片、重复冲突、篡改、混合候选、过期来源或解压异常必须拒绝；部分写出不整帧重放。
- 模型输入超限不能靠管道分片假装已解决。若无法在现有外发范围、请求数和时限内完成，停止相关模型阶段并请求明确授权，不自动加调用。

## 8. 离线验收与反向审查

未来工程阶段在实际目标工作区运行，使用已有 Python 环境、标准库、本地夹具和假网关；不联网、不安装、不导入执行待分析项目。

必需测试分类：

1. 软目标越界正控：33 个及更多必需节点，超过 98,304 字节正文，超过 240,000 字节骨架，原借槽冲突；必需集合不变且产生告警。
2. 不可压缩核心：超过 22,016 字节后在新版能力下大帧或分片成功，独立消费者恢复完全相同的必需内容。
3. 正文与边闭包：巨大定义、装饰器、条件、循环、跨文件调用、动态目标未知和不同源码编码，不删除必要支持。
4. 进展保护：新关键证据与噪声交替出现；保护相关证据而非放行全部历史。
5. 遥测：边界计量、提醒去重、摘要自增量、日志故障、真实写出与消费状态区分。
6. 安全负控：篡改、缺片、混合快照、来源变化、取消、断管、慢消费、硬超时和清理未知仍不通过。
7. 兼容回归：旧版本仍保留原拒绝条件，新版本越界正控不能替换旧版本的有效负控。
8. 棕地文档：完整结构用于渲染，分卷可遍历全部骨架和未完成义务，不能以传输预览充当完整原件。

独立预期集合不使用生产选择器作为唯一神谕；旧策略与新策略对照相同夹具，记录覆盖、字节、耗时和提醒，不预设性能改善。

## 9. 裁决、未验证项与执行交接

裁决：方向可行，必须端到端整改，不能仅调大常量或取消生产者抛错。最小表示以保真为约束；不承诺全局最短表达、无限输入或任意宿主零故障。
