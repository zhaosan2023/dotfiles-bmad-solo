# ADR：动态背压松绑与无损蒸馏

选择“保真硬门禁、预算软背压、传输能力协商”三层架构。固定块数和字节目标不再裁减或阻断新版中的必需信息，实际权限、来源完整性、协商能力和资源故障仍构成停止边界。

## 1. 状态、绑定与替代范围

- 本 ADR 按当前用户明确转正授权与独立批准为 ACCEPTED，仅接受已确认的离线实现及 G1 规范决策，不证明真实宿主加载、模型消费或全项目业务正确性。
- 绑定[分析草案](../analysis/ANALYSIS-20261028-adaptive-backpressure-and-lossless-distillation.md)及[Task Unit](../../specs/tasks/archive/20261028-adaptive-backpressure/TU-20261028-ADAPTIVE-BACKPRESSURE.md)，不接管其他活动计划。
- 正式定向替代[旧 ADR 的 E2 配额条款](ADR-20261025-solo-distill-v2-risk-remediation.md:46)及[旧 ADR 的 E3—E5 帧政策](ADR-20261025-solo-distill-v2-risk-remediation.md:58)中“固定配额决定新版必需内容可交付性”的部分。
- 保留旧 ADR 的来源身份、完整正文、条件与关系闭包、消费者独立认证、版本兼容、取消和实际传输故障决策。不修改旧接受状态、授权或历史回执。
- 定向替代关系在本次明确接受边界正式生效；旧协议未显式启用新策略时保持原行为。旧 ADR 的 ACCEPTED 状态及历史验收记录不改写，安全硬边界不降为软提醒。

## 2. 背景

现有五层限制叠加：正文最多 32 块和 98,304 字节、导航骨架最多 240,000 字节、V2 调度采用 16/12/4 与借槽政策、V2 A 发布按 22,016 字节完整帧限制、棕地文档入口从受限结构副本展开。

这些限制并非同一资源单位。旧读取器超额时跳过完整定义或拒绝，不宜笼统称为正文截断；旧交付摘要另有文本缩短与指针子集。详细证据与路径见[五层病灶](../analysis/ANALYSIS-20261028-adaptive-backpressure-and-lossless-distillation.md)。

用户要求以业务不变量无损为前提消除表示冗余，不能为了满足任意软目标删除核心骨架、调用支持、未完成义务或失败证据。

## 4. 决策一：保真硬门禁

1. 验收前冻结项目、快照、范围、契约版本及非空必需集合。业务不变量和已知调用边分别定义分母。
2. 先归并必需来源、完整正文、条件、关系和义务支持的传递闭包，再选择可选材料；唯一所有者计费不删除多项支持关系。
3. 不裁减必需事实的否定、条件、所有权、副作用、证据等级、来源身份、失败原因和未完成义务。
4. 未知动态调用保留调用点与原因，不伪造已消歧边，不计为已满足强语义义务。
5. 骨架完整登记后稳定分页；单个巨大定义不得截取前缀或用类头伪装完整定义。
6. 可做确定性去重、公共引用及无损编码，不承诺数学上的全局最短表达。
7. 必需信息仍有缺口时不能接受贡献，即使软预算记录完整、编码成功或退出码为零。

## 5. 决策二：预算软背压与遥测

- 32 块、98,304 正文字节、240,000 骨架字节及旧帧目标在显式新策略下作为规划观测值，不作为必需信息淘汰条件。
- 16/12/4 分类保留为调度提示，不以必需借槽冲突拒绝完整闭包。探索、组合搜索和真实资源限制仍受控。
- 遥测职责收集运行身份、各阶段耗时、唯一正文块数、正文字节、核心与编码字节、精确单帧及累计字节、目标、协商硬能力、告警、策略和结果。实现依据为用户确认的 solo-distill-mcp 完工回执；本轮未读取目标源码，不构造模块、类或提交身份。
- 近预算比例版本化配置；跨越状态或阶段时提醒，重复事件聚合。纯软超限产生 Warning，不抛致命容量异常。
- 后台记录指观测职责，不默认启动后台线程、进程或网络任务。协议标准输出不得混入日志，标准错误提醒须去重和有界。
- 写出耗时与结果在真实回执后记录；未知模型能力、成本和内部调用保持未知。待发送帧冻结，不为补写遥测修改已认证核心。
- 必需遥测证据丢失时相应验收保持未知或阻塞，不因此删除业务原件或冒称成功。

## 6. 决策三：面向对象分层与进展保护

- 业务保护策略负责声明必需根与闭包，上下文管理负责表示选择，传输底层负责编码、协商及写出。
- 上下文策略通过继承复用既有能力，以方法重载增加字面量或证据保护；调用父实现不是安全证明，最终输出仍核验闭包。
- 新必需来源、条件、关系、拒绝原因或未完成义务的可核验变化形成进展事件，更新保护集并绕过相关有损压缩。
- 不以模型自报进展放开全部日志、历史或可选探索；不阻止无损传输编码。
- 子类和预算策略不得取消权限、来源、输入、解压、硬截止和实际写出检查。

## 7. 决策四：大帧或分片协商

1. 使用显式新策略／协议版本；旧 V1、V2 和场景 B 保持原行为，不静默越限。
2. 将软帧目标、调用者明确硬上限、消费者能力、解码资源上限分别记录；未知能力不能当作无限。
3. 双方确认更大帧能力时完整帧可超过 22,016 字节并告警；否则采用双方支持的分片机制。
4. 每片绑定项目、快照、契约、包身份、编码、序号与完整性摘要。清单声明总片数、总字节、总摘要及完成标记。
5. 通过已声明的独立分页调用或通知机制交付，不向同一请求发送多个未声明的最终响应。
6. 接收者完成重组、身份、源码支持与闭包认证后才认定完整知识交付。原件指针或仅发送成功不证明已经消费。
7. 缺片、重复冲突、篡改、混合候选、过期身份、解压异常或断管保持拒绝。部分写出不得整帧重放。
8. 模型输入、外发范围、请求数及运行时限是独立约束，管道分片不自动解决模型输入问题，也不扩大外发授权。

## 8. 被否决方案

| 方案 | 否决理由 |
|---|---|
| 暴力截断正文、骨架或必需结论 | 删除条件、否定、支持边和义务，无法满足保真验收 |
| 仅调大所有常量 | 保留同类死锁，不解决真实能力和资源边界 |
| 仅删除生产者抛错 | 旧客户端和消费者仍拒绝大帧，形成兼容性故障 |
| 所有错误降为 Warning | 掩盖权限、来源变化和真实传输失败 |
| 指针保存即视为完整消费 | 无法证明下游读到全部必需证据 |
| 无限候选、无限驻内存或自动增加模型调用 | 违反真实资源和授权边界 |
| 直接覆盖旧 ADR 的接受与验收记录 | 混淆历史事实与新决策，不可审计 |

## 9. 影响范围与兼容策略

G1 已同步[数据交接](../../specs/governance/03-dataflow-contracts.md:183)、[门禁](../../specs/governance/04-kcp-sod-gates.md:126)、[预算](../../specs/governance/01-plan-act-role-embedding.md:118)和[宿主适配](../../specs/governance/05-host-adaptation.md:150)及确有冲突的预算分发源；六份治理文件已迁入独立领域目录。验收仅为获准文档差异审查，不证明宿主加载、实际分发或治理控制器生效。

代码整改要求覆盖 solo-distill-mcp 的正文读取、蒸馏、遥测，以及实际 V2 调度、候选、核心、传输、消费者和棕地链。新版用正控验证软目标越界，旧版仍保留有效负控，不通过降低断言或删测试取得通过；本轮接受来源为用户确认的离线完工回执，不冒称重新检查了目标源码。
