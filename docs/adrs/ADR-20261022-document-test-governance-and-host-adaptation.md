## 1. 背景与决策范围

需要治理的是长期测试、临时验证、运行证据、领域规范、决策历史和执行契约的职责边界，而不是单纯减少文件数。目录整洁不能优先于语言封装、回归覆盖、唯一证据和旧任务保护。

旧[`活动计划`](../../_bmad-output/pending_implementation_plan.md:2)仍为 BLOCKED，旧[`ADR`](ADR-20261021-v4-attended-repair-and-repository-cleanup.md:3)仍为 PROPOSED。其真实宿主验收尚未完成，不能由本提案接受、冻结或归档。旧任务已列明的验收及条件收尾授权保持独立。

## 2. 决策

提出“通用项目导航、职责分离、薄宿主适配、分阶段演进”的条件方案；现有布局作为过渡及不满足新接口条件时的退路。结晶保存及当前获准继续均不表示 ADR 已接受、实现已完成或运行验收通过；具体阶段执行、预算和门禁由绑定计划承载，进度不镜像到本 ADR。

### 文档职责

- 项目入口候选为根目录[`AGENTS.md`](../../AGENTS.md)：稳定导航、操作纪律、构建与验证入口，不保存逐轮进度，不整体复制项目事实基线。
- 领域规范候选为[`specs/`](../../specs/)：当前需求、接口、不变量与验收，引用必要 ADR，不吸收全部决策历史。
- 架构决策暂留[`现有 ADR 目录`](../../_bmad-output/adrs/)：背景、取舍、后果和替代关系；保留必要提案与历史。目录是否迁移是后续契约，不是本轮动作。
- 计划保存目标、授权、依赖及验收；每个任务显式绑定契约。旧默认入口不腾空，新计划仅使用独立、经确认且实际允许的路径。
- 分析材料区分当前、历史、被替代及待核验；默认不加载历史不等于删除历史。提炼结论保留来源、适用范围及未知。

### 测试与证据

- Python 优先复用集中测试目录；Go 白盒需访问未导出成员时保留业务包，不为迁出导出内部状态、复制实现或削弱断言。
- 模块和契约与测试为多对多关系。先复用已有目录及验证入口；只有真实检索困难才增加映射，不建立第二份状态账本。
- 持久回归、必要跨组件测试和夹具按缺陷、契约及副作用边界判定，不凭工单编号或文件名认定无价值。
- 提交、产品分发、测试运行和证据保留分别裁决。长期回归不能整体忽略；临时探针不默认进入长期资产，运行输出不充当测试代码。
- 原始回执的可信度取决于来源及完整性，不取决于是否位于临时目录。清理前检查引用与唯一证据依赖；模型摘要不能替代唯一原始结果。

### 方法论与生命周期

- 全局方法论不吸收未经确认的项目特例；助手可依据证据提出项目需求，重大变化由用户确认。动态背压发现不自动升级为全局规则。
- 只有重要新取舍才新增 ADR；既有有效决策直接复用。测试通过不自动改变需求、接受 ADR 或更新项目规范及事实基线。
- 完成计划采用日期和唯一标识；未完成冻结另带明确冻结后缀并保留未完成语义。冻结不是完成，恢复须另获授权、新建实例并重验；本轮不冻结旧任务。

### 宿主适配

- 单一权威项目内容源，加薄宿主桥接，不双写项目上下文。
- Cline 官方将 Plan 定位为不改变文件的探索规划，将 Act 定位为按计划实施。[4] 因此设计默认 Plan 会话分析，持久化经单独获准写入步骤；目标版本的终端限制与保存接口仍待核验。
- 规则加载、技能调用、模式切换与工具权限分别验收。目标版本接口未核实前不编造模式条件字段或桥接发现路径，不承诺自动加载或自动调用；安装资产不证明扩展激活，薄路由不证明程序权限隔离。
- 钩子配置、脚本失败和执行后工具结果不能单独证明异常时默认拒绝、结构化验证通过或推进前门禁。目标接口不足时保持相关出口 BLOCKED，不降低补充提案的原生体验或硬背压验收，不修改私有分支或另建通用控制器。
- 点击 Act 不自动授予本项目的全部实施权限；须绑定用户批准的计划、阶段、写入范围及客户端审批。Roo 保留宿主权限适配，静态配置不证明运行时拒绝。

## 3. 候选与被否内容

- A：保留旧布局、补职责与生命周期。改动小，作为过渡或回退；不证明跨宿主自动接管。
- B：通用入口与目标布局、薄适配、分阶段演进。推荐条件方案；路径契约、宿主支持及迁移回归门禁仍待满足。
- C：激进集中、合并或忽略。机械迁出白盒、丢回归、删除唯一证据、合并全部 ADR 或覆盖旧计划的变体违反硬约束，不采用。

不采用固定窗口比例、行数阈值、评分、提速承诺、全部门禁 PASS 或“无未知”。Huntley 作者原文的跨语言移植主题已核实，具体测试提炼步骤未由本次片段核实。[9] HumanLayer 一手文章支持有意识组织模型上下文的方法。[8] 本提案不由这些方法推出删除日常回归、唯一证据或必要历史的义务；具体作者署名及未展示的步骤不作为必要决策前提。

## 4. 后果与 DR 防护

职责分离增加少量导航维护；以相关引用和现有验证入口约束成本，不另造部署框架、经验库或状态账本。

迁移须先确认权限、逐文件范围、源身份、引用和唯一证据，再分批保全及适配。源变化、迁移中断、引用失效、测试发现丢失、私有成员访问失败或宿主未加载时停止对应步骤，保留源与用户改动，不降低验收。

新治理不依赖旧任务先完成，但不得占用其入口。接口或宿主不支持时保留现有布局与显式读取，不强推迁移或用软链接绕过受管资产保护。

旧[`V4 返修提案`](ADR-20261021-v4-attended-repair-and-repository-cleanup.md:41)保留相关验证与属性测试互补的约束，本提案增加资产职责及宿主桥接取舍，不替代其未完成验收。

## 6. 接受条件与交接

本 ADR 保持 PROPOSED。后续执行只消费已绑定契约，按[`真实计划模板`](../../bmad-suite-v4/skills/bmad/references/templates/implementation-plan.template.md:1)明确当前阶段、权限、命令、环境前提、验收与失败恢复；未创建资产不标可用。F2 的独立适配资产通过不代表硬门禁或整个阶段通过，更不自动解除 F3/F4 依赖。

接受须另获工程授权，完成所绑定契约的全部必需验收，并取得对应转正授权。路径与引用、测试发现和必要断言、证据保留及实际采用的宿主支持分别提供真实结果；不以静态配置或隔离分发替代必需宿主交互。

结晶阶段未实施、未测试或迁移；此历史描述不替代当前真实回执。当前执行范围由绑定计划承载，F3 逐文件迁移、F4 真实宿主验收、接受 ADR、更新事实基线及归档仍须分别满足授权与门禁；不关闭或变更其他任务。
