## 1. 决策摘要

采用“显式任务优先、活动计划绑定、归档只读发现、授权恢复”的三级计划路由，替代固定先读暂存计划的单向规则。以受管文件集的物理复制取代共享规则目录的删除式镜像，并补齐模式权限隔离和可验证的治理闭环。

本决策已按第 10 节所述的仓库交付边界接受。受管部署已有物理复核；客户端加载、权限执行和完整生命周期交互仍不作为本次已验证事实。第 2 节保留立项时审计快照，不代表整改后的现状。

## 4. 三级自适应路由契约

### 前置门禁：先判断意图和授权

先区分只读审计、方案结晶、实施、继续及重放。读取计划不等于获准执行计划；只读任务不得进入实施、转正或归档流程。能力不足时披露未验证状态，不越权获取 Git 或终端证据。

### Level 1：用户显式输入优先

用户指定计划时直接读取该文件，跳过默认暂存路径；不得让其他计划抢占当前任务。

显式路径不存在或内容非法时，进入可恢复阻塞状态，说明原因。可检索归档并提出候选，但不得静默替换用户指定文件或执行其他任务。自动降级指发现候选，不是转移执行授权。

### Level 2：活动工程态探测

仅在没有显式计划时探测[暂存计划](../pending_implementation_plan.md)。存在且与当前任务相关、契约有效时，绑定其路径、计划标识、内容指纹和当前阶段。

暂存计划不相关或存在多个活动任务时，保持原件，明确冲突；不得因固定文件存在而自动执行。开始修改前复核契约未被替换。

### Level 3：归档与空闲态优雅降级

默认暂存文件不存在属于正常生命周期状态，不反复读取同一路径，不把工具返回的文件缺失视为整个任务崩溃。

- 用户要求继续历史任务：检索[归档目录](../archive/plans/)，展示候选状态与匹配依据；不得仅按时间选择最新文件执行。
- 候选不明确：请求选择；没有候选且需要新方案时提示立项。
- 已有明确的小修复或配置任务：按轻量流程处理，不强迫持久立项。
- 已完成、已暂停或已归档计划默认只读；恢复需要明确授权，建立新的执行实例，保留来源并重新验证，不能继承历史绿灯。
- 权限拒绝、磁盘错误和内容损坏不得冒充“文件不存在”。

### 状态推进与结束

```text
INTAKE → READ_ONLY / IDLE / NEEDS_SELECTION / READY
READY → EXECUTING → VERIFYING → COMPLETED → ARCHIVED
任一执行阶段失败 → BLOCKED
明确暂停 → SUSPENDED
恢复 → 重新校验后 READY，不跳过验证
```

成功闭环只处理本次绑定的活动计划。先确认归档写入成功，再处理活动副本；禁止归档其他暂存任务或覆盖历史输入。新方案完成不代表暂停任务自动完成。

## 5. 权限与方法论防护锁

- 分析模式不授予终端能力；编辑权限限制为授权的 ADR、分析产物和计划路径，明确排除生产文件与项目事实基线。路径正则及拒绝效果须在目标 Roo 版本验证。
- 工程模式具备实施能力，但每条终端调用均绑定单飞、分级超时、前台同步、标准输入封闭及工具正交；不得把所有程序都机械添加同一种非交互选项。
- 全局启动规则按模式实际权限降级，分析模式没有终端时不强制获取 Git 状态。
- Type A 只在会话交付，零持久文件；Type B 在授权后结晶。任务复杂度不能推翻只读授权。
- 保留 Mary 的目标—约束—结论—证据结构、Keshav 三读法、硬门禁和四个收敛锁；选型评分必须有依据。
- 结晶前检查历史不变量和未完成计划；冲突须明确处理，不覆盖活动任务。分析阶段不得把提案写成项目事实。
- 原生 Skill、Roo 入口和计划模板同步定义核心契约，平台特有工具行为分别适配，不照搬不支持的参数。

## 6. GitOps 决策

### 受管资产与物理复制

[套件目录](../../bmad-suite-v4/)是实现源，全局 runtime 是分发目标。采用受管文件清单、摘要与所有权记录；共享目录内未知文件不删除。遇到用户修改或首次同名接管冲突，保留并报告。

检查源、目标和父目录链接；默认拒绝不满足物理部署边界的目标，不静默跟随链接。卸载只处理明确受管且允许删除的规则与模式，保护第三方资产。

### 预检、合并与恢复

全部目标写入前统一完成依赖、结构、权限和链接预检。损坏 YAML、重复键、重复模式标识及错误结构失败关闭，不以空配置覆盖旧文件。

使用参数传递路径、字节备份、同目录临时文件及原子替换。对多文件与多 IDE 目标采用部署锁、提交前指纹复核和恢复日志；不宣称跨目录整体原子性。

### 环境、版本与模拟执行

支持现有三类固定候选布局并允许显式目标配置，报告命中及跳过原因。零模式目标不得称完整激活；项目级同名模式只诊断，不自动删除。

模拟执行必须在任何修改前生效，覆盖更新、标签缓存和分支切换。清单记录实际选中提交及文件摘要；切换失败必须显式失败。降级到无 Roo 源的版本时明确拒绝或经授权处理旧受管资产，不静默混用版本。

## 7. 验证与 ADR 生命周期

实施划分为规则路由、权限治理、分发保护、版本溯源和运行时验收阶段。各阶段采用相关配置校验与隔离分发契约测试，不运行业务单测。

基础静态命令，均由后续具备权限的工程会话执行：

```bash
timeout 15s bash -n bs.sh < /dev/null
timeout 15s bash -n install.sh < /dev/null
timeout 15s git --no-pager diff --check < /dev/null
timeout 15s ./bs.sh --status < /dev/null
```

状态查看仅提供诊断，不是配置语法校验，也不是完整验收。后续计划须建立实际存在的配置校验器与隔离测试后再执行，不引用尚未创建的测试作为已通过证据。

用户提供的状态命令保留为计划追溯输入；真正执行必须有超时边界，并在工作区根目录运行。验收至少包含：显式路径优先、缺失路由、暂停恢复、只读零写入、越权拒绝、三环境合并、第三方配置保留、损坏输入不写入、链接拒绝、幂等、模拟执行零副作用、卸载保护及失败恢复。

本 ADR 只有在相关实现、验证证据和架构边界完成对账后，才可由工程阶段转为 ACCEPTED。原定运行时缺证据阻塞条款，经本次人类架构师明确裁决，按第 10 节调整为宿主平台职责委托；不是以状态命令成功替代运行时验证，也不改变其他任务的门禁。

## 9. 否决方案与风险

- 否决只修改工程入口一句话：全局规则、原生入口及完工清理仍可能抢占任务。
- 否决自动执行最新归档：文件时间不是执行授权，也不能证明任务匹配。
- 否决仅靠提示词阻止生产写入：必须同时验证配置权限边界。
- 否决共享目录删除式镜像：目录一致性不能优先于用户资产保护。
- 否决仅删除危险选项即宣布完成：仍需所有权、失败关闭、并发和恢复契约。

新增校验和清单带来维护成本；以少量明确阶段和相关测试控制复杂度。若时间不足，优先交付资产止损与生命周期修复，但不得将分阶段交付描述为本 ADR 全部验收完成。
