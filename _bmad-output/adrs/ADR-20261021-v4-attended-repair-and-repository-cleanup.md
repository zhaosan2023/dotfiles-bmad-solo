# ADR-20261021：V4 人值守工程返修、版本收敛与安装分发入口简化

- Status: PROPOSED
- 创建日期：2026-10-21。
- 决策所有者：项目维护者。
- 关联计划：[V4 分阶段计划](../pending_implementation_plan.md:1)；计划标识 BMAD-V4-ATTENDED-CLEANUP-20261021-01。已取得写入成功回执并全文回读；当前入口绑定此 V4 计划，不恢复 V5。工程接管仍须核对实际授权、候选变化和阶段门禁，文档保存不表示验证通过或宿主已加载。
- 会话标识：null。
- 当前授权：2026-10-22 用户授权继续关联活动计划及本 ADR，以全部必需门禁通过后的转正与归档为目标；工程取舍可通过硬门禁及 DR/DM 自治决定，在当前技术栈落实类型契约、属性与确定性模糊输入背压，保护既有改动，不重复清理或恢复 V5。前序本地清理范围及 V5 独立迁移的用户确认保持历史语境，不作为本仓库独立实测的迁移结论。

## 1. 背景与证据边界

项目当前目标改为人值守的 V4 工程套件；无人值守工程计划迁往独立项目 solo-engine。此前 V4 分析入口优化及其 DR/DM 报告需要返修，不能以文字赋权或评分表证明已经落地。

- 返修前的分析入口曾宣称免审批只读命令和草稿探针执行权；[旧报告的赋权声明](../../docs/Ralph-Wiggum-Loop/dr_dm_v4_backpressure_optimization.md:50)保留这一问题背景。[Roo 模式配置](../../bmad-suite-v4/roo/settings/custom_modes.yaml:5)的分析权限只有读取、受限编辑和浏览，入口文字不能扩大权限；[当前技能的权限边界](../../bmad-suite-v4/skills/ana-solo/SKILL.md:25)是返修候选，不能当作返修前原文或宿主加载证据。
- 接管时发现技能计划示例使用未支持的验证类型，命令缺少超时和封闭输入；历史问题与依据保存在[返修分析](../analysis/ANALYSIS-20261021-v4-backpressure-repair.md:43)。[现有模板](../../bmad-suite-v4/skills/bmad/references/templates/implementation-plan.template.md:20)与[校验器](../../scripts/validate-roo-contracts.py:175)限定三种验证类型；[当前技能](../../bmad-suite-v4/skills/ana-solo/SKILL.md:79)引用套件内模板，不为了示例新增验证协议，不将已删除的示例行号作为当前定位。
- [旧 DR/DM 报告](../../docs/Ralph-Wiggum-Loop/dr_dm_v4_backpressure_optimization.md:30)含未经测量的智能程度、注意力释放及提速断言，[其防线](../../docs/Ralph-Wiggum-Loop/dr_dm_v4_backpressure_optimization.md:90)没有定位真实实现，[其结论](../../docs/Ralph-Wiggum-Loop/dr_dm_v4_backpressure_optimization.md:149)把部分文本修改写成完整落地。该报告不作为接受决策或性能基线。
- [部署入口](../../bs.sh:109)集中处理参数、更新、新版移交、标签来源和分发；[安装入口](../../install.sh:67)调用它完成安装或更新。简化必须保留已有失败关闭和所有权边界，不按行数删除保护。
- 接管时[套件映射](../../scripts/suite_versions.py:29)、[CI](../../.github/workflows/ci.yml:55)和测试存在多版本依赖；本轮须同步退役分支和相关回归，不能只删目录留下悬空契约。
- 旧通用套件此前身份待确认；最新用户已明确授权删除该目录，不再依赖插件通用名称推断版本。未列入清理清单的资产继续保护。
- V5 计划已取得完整冻结保全及源复核回执，实际目标为[V5 冻结计划](../archive/plans/plan-20261021-BMAD-ANTI-BUREAUCRACY-20261012-01-frozen.md)；[V5 ADR 头部](ADR-20261012-bmad-solo-anti-bureaucracy-and-programmatic-guards.md:14)标注暂停和历史路径语境。冻结不表示开发完成或宿主进程已停止。

本次结论基于仓库静态读取及客户端保全回执。旧任务通过记录不继承为本任务绿灯；用户使用体验是问题线索，不是对照测量。

## 2. 三遍阅读的收敛结论

- 第一遍：这是工程方法论与分发边界的结构型整改。目标是可用、易维护的人值守 V4，不是继续建设无人值守控制平台。
- 第二遍：核心因果缺口是入口文本、实际权限、计划契约及分发链路没有闭合；“禁止终端必然导致分析瘫痪”与“属性测试必然替代大部分回归”均未获证明。
- 第三遍（初始决策语境）：先删旧版本会破坏映射、缓存和测试；在同一会话中热换规则会使能力试验身份不清；仅移动旧报告会保留不实结论。因此最初提出“先返修、验证和确认有效加载，再开展 V4 clean 试验”。当前授权已明确调整依赖：保留阶段 1 本地出口，阶段 2 宿主验收后置，不阻塞获准阶段 3/4 本地清理；不由本地结果推断宿主加载。此说明保留初始理由，不追改历史已接受记录。

## 3. 决策与替代项

### 决策一：最小充分返修，不扩大分析权限

保留三遍阅读、目标与非目标、证据分层、硬门禁先行、反向审查及条件可行裁决。删除无依据的数字、固定非目标数量、所有假设必须先实测、所有分析必建 ADR 等机械要求。

分析入口继续只读取证及获准文档结晶，不授予终端或生产编辑权限。必要实测列出明确问题、实验范围和验收，交给已获准工程入口执行；结果按真实回执返回，不自动启动实验、不取消客户端审批。原生 Skill、Roo 规则、模式说明、共享核心与下层流程须一致。

否决直接给分析模式增加终端组：当前没有执行级沙箱，草稿路径不是隔离证明；增加权限不是解决本次冲突的必要条件。若未来确需独立实验模式，另行决策和验证。

### 决策二：相关测试与属性测试互补，不按比例删测

普通工程失败可在当前范围和预算内修复，失败不推进依赖、不交付为完成。验证覆盖受影响接口、调用方、所有权和真实副作用；不能机械缩小为只测被编辑函数。

属性测试适用于可定义的不变量，不能替代已经发现缺陷的回归或必要的 I/O、并发与恢复边界。没有真实维护成本与覆盖依据时，不执行“删掉 90% 测试”、固定评分或固定提速承诺，也不为所有任务安装新测试框架。

本次背压取舍采用定性 DM，不另造分数：

- 选用当前 Python 标准库的类型化故障输入、显式运行时身份校验及固定种子属性生成，复用[身份属性测试](../../tests/roo_distribution/test_suite_identity_properties.py)；合法分支和各故障分支均须命中，验证输入不变性、同种子重放及神谕对无条件接受、无条件拒绝和输入污染的识别能力。
- 保留[状态接口缺陷回归](../../tests/roo_distribution/test_suite_status.py)、普通安装与分发调用方，以及[显式退役的隔离事务回归](../../tests/roo_distribution/test_retired_deployment_migration.py)；纯输入属性不替代实际所有权、锁、恢复及第三方保护边界。
- 不采用仅有固定样例或全部拒绝的弱神谕作为唯一防线；也不为本任务迁移 Rust、引入第三方测试框架或恢复 V5 控制器，避免扩大依赖及授权范围。

DR 反向审查：类型标注和枚举不提供 Python 静态强类型证明；固定种子生成不等于覆盖率引导模糊测试、通用反例收缩或完整系统确定性。神谕与实现可能共同遗漏规范，故保留独立缺陷回归及必要集成边界；上述取舍不证明 Roo 宿主加载、权限执行或绝对无缺陷。若后续需要新增依赖或更强探索引擎，先取得相应授权并明确验收。

### 决策三：旧报告返修归位，决策与进度分离

经工程核对后，将旧 DR/DM 的有效比较与证据修订为项目分析产物，规范位置为 [V4 返修分析](../analysis/ANALYSIS-20261021-v4-backpressure-repair.md)。本 ADR 保存决策和替代项；计划保存目标、授权、依赖与验收，平台任务记录保存本阶段实际进度和回执，不建立第二份流水账。

旧文件的移动、保留说明或退役方式先查引用与已有改动；不只移动原文，也不覆盖用户另有修改的研究笔记。不能让外部项目笔记成为本项目默认决策目录。

### 决策四：仅保留 V4，按最新授权直接清理并简化入口

V4 是本仓库唯一套件，阶段 1 本地验收不等于宿主加载。本轮最新授权将阶段 2 后置，直接实施阶段 3/4，不重复完整分析、不伪称已建立新 V4 宿主会话；真实切换与交互验收仍是独立未完成项。

按明确路径删除旧通用套件、V3 和 V5 源码及专属测试，清理指定失效文档与无引用临时草稿。保留 V4、历史 ADR、冻结计划、回执、退役 DR/DM 原稿导航及被引用材料，保护范围外用户修改，不进行危险 Git 清理；删除后立即运行相关 V4 契约回归。

安装入口负责环境前提、可信来源获取与调用；部署入口负责明确意图、预检及受管分发。两者复用现有来源、所有权、缓存、事务及恢复原语，先删除重复职责和失效版本分支，不复制第二套部署框架。兼容别名是否保留以真实使用和迁移成本决定，不任意重命名接口。

普通安装、更新与部署唯一支持 V4，删除多版本选择和 V5 自动迁移或激活分支。已存在的非 V4 或未知受管身份失败关闭，不默认覆盖，也不由显式 V4 别名绕过保护；保留相关拒绝、无副作用、来源缓存和事务回归。

允许保留[显式一次性受管退役入口](../../scripts/migrate-retired-deployment.py:37)，但真实目标处置须另行授权：只接受已核验 V5 身份，精确覆盖历史受管模式目标，复用现有所有权、锁、清理门禁、预检与事务，不接管未知或用户修改资产，不加载退役代码或恢复 V5。它不属于普通安装/更新/部署调用链的自动迁移分支；本次仅通过[项目内隔离回归](../../tests/roo_distribution/test_retired_deployment_migration.py:29)及显式 CI 收集契约验证。磁盘事务不证明新 V4 宿主会话身份或交互验收，宿主验收后置、不阻塞获准本地清理。

### 决策五：V5 独立于本仓库，源码和专属测试明确退役

最新用户确认已完整保全并独立迁往 solo-engine，明确授权直接删除本仓库 V5 源码与专属测试，替代此前“暂留源码、只评估迁移”的决定。本轮不访问或修改外部项目，不将用户确认写成本仓库独立核验结果。

保留[V5 原提案](ADR-20261012-bmad-solo-anti-bureaucracy-and-programmatic-guards.md)和[V5 冻结计划](../archive/plans/plan-20261021-BMAD-ANTI-BUREAUCRACY-20261012-01-frozen.md)及真实回执；其中源码路径属于历史语境，不证明现存资产或继承权限。V5 未完成承诺不因本仓库退役而标记完成，不继续其开发或启动任务。

## 4. 不变量与历史关系

- 保留[已接受生命周期决策](ADR-20261008-roocode-bmad-v42-lifecycle-and-governance.md:77)的分析权限、显式计划优先、历史恢复授权和受管资产保护；本提案不修改其接受记录。
- 替代旧 DR/DM 中未接受的免审批探针、无依据评分和效果断言；不把非 ADR 的报告声明当作既有接受决策。
- V5 的当前暂停及迁移意向独立于新 V4 任务；V4 阶段成功不完成 V5，不恢复其任务。
- 一份有效任务契约、一个当前写入者；切换前核验在途进程和用户改动，无法确认则阻塞相关写入。
- 配置分发不等于宿主加载，模式展示名称不等于版本身份，空输出不一律等于失败；以具体操作的必需证据判断。

## 5. 风险、验收及接受边界

分阶段验收和实际命令只保存于[关联计划](../pending_implementation_plan.md)，ADR 不镜像任务状态。阶段交付不等于全计划完成；本轮相关验证失败不得推进，真实宿主身份和加载证据缺口不被本地清理通过掩盖。

接受本 ADR 前须完成：两入口契约对齐、旧报告事实修复与路由、实际 V4 切换证据、范围明确的版本清理、安装分发相关回归及保护边界对账。2026-10-22 用户已给予全部必需门禁通过后的转正及全计划完成后的归档授权，但授权本身不提供缺失证据；必需宿主验收未通过时保持 PROPOSED，保留活动计划，不以局部交付闭环。不足以比较优化前后效率时明确无对照结论。
